# 后量子密码机原型 —— 演示说明

一页纸：这台机器怎么分工、怎么连、怎么跑演示、演示证明了什么。

---

## 这台机器怎么分工

一块 Zynq UltraScale+ 板子（XCZU3EG），三层各管一件事：

| 层 | 做什么 | 手里有什么 |
|---|---|---|
| **TEE**（OP-TEE 里的 TA，安全世界） | **密钥管理**：生成种子与对称密钥、用 KEK 包成 blob、需要时解开并经安全通路装进 FPGA | 明文密钥（只在用的那一刻）；KEK 永不出 TA |
| **FPGA**（PL） | **密码运算**：ML-KEM、ML-DSA、AES / SM4、SM3、真随机数 | 私钥每次从种子现展开、算完由硬件擦；对称密钥在金库里没有读出路径，会话结束即擦 |
| **普通世界**（Linux：daemon + libsdfe） | **调度与接口**：串行化硬件访问、对外提供 SDF / PKCS#11 / 远程 mTLS | **只有句柄和密文 blob**，一个明文密钥字节都没有 |

一句话：**明文密钥只存在于 TA 和 FPGA 里。** 普通世界即使被拿下 root，
也拿不到密钥、装不进自己的密钥（FPGA 的装载口只认安全世界，EL3 白名单也把它排除了）。

分组加解密这种高频操作**不进 TEE**：密钥已经在 FPGA 里，daemon 按槽号直接驱动，
每个分组不走 TA。只有"生成 / 装载密钥"走一次安全世界。

## 一、接线

板子上有**两个网口**，请**两个都插**：

| 网口 | 接口名 | 地址 | 说明 |
|---|---|---|---|
| PL 侧 | `eth0` | `192.168.50.174` | 网卡在 FPGA 里，**装入密码位流后会消失**，正常 |
| PS 侧 | `eth1` | `192.168.50.175` | **演示用这个**，不随 FPGA 重配而消失 |

串口（备用）：Micro-USB，**115200 8N1**，`root` / `root`。

---

## 二、上电

插电，等 **约 35 秒**。全自动：配好 `eth1` → 装密码位流 → 打开安全世界通道 →
把 TA 就位 → 起密码机服务（含远程端口）。确认就绪：

```
ssh root@192.168.50.175 cat /media/sd-mmcblk1p2/hsm/HSM_STATUS
```

看到 `READY=yes` 才算就绪。每一行都是实测的：比如 `DAEMON=ok` 的前提是服务
启动时真的经 TA → EL3 → FPGA 把种子通路走通了，走不通它会拒绝启动。

## 三、跑演示

```
ssh root@192.168.50.175
sh /media/sd-mmcblk1p2/demo/run.sh            # 约 1 分钟
sh /media/sd-mmcblk1p2/demo/run.sh --mgmt     # 另附软件密码机的管理功能面
```

脚本在仓库里是 [board_demo.sh](board_demo.sh)，主体程序是 [demo_tour.c](demo_tour.c)
（一个普通应用，只链接 `libsdfe`，一行密码运算都不做）。五段：

| 段 | 内容 |
|---|---|
| 〇 架构一页纸 | 上面那张分工图 |
| 一 设备就绪 | 各层状态 |
| 二 走一遍 | **A 密钥管理在 TEE**：后量子私钥由 TA 保管种子；对称密钥 TA 生成 → blob → 重装；篡改 blob、明文导入都被拒；KAT 只进专用槽 7<br>**B FPGA 做运算**：ML-KEM-768、ML-DSA-44/65/87、AES/SM4 四种模式、SM3、随机数 —— 每项对官方向量，并给出端到端时延<br>**C 会话结束**：句柄作废、FPGA 里的残留被擦 |
| 三 调用走了哪条路 | 从 daemon 日志里摘出本次运行的每类调用，对照它经过的层 |
| 四 从硬件侧核对 | 直接读 FPGA：会话结束后金库为空；普通世界绕过 TEE 往装载口写密钥 —— 一笔都不生效，且被计数 |
| 五 上层怎么调用 | SDF C 接口、远程 mTLS、PKCS#11 |

### 从另一台机器调用（同一内网）

远程口是 mTLS（双向证书）。仓库里一条命令：

```
./demo/remote/run.sh <板子IP>
```

或自己写程序：把 `SDFE_OpenDevice` 换成 `SDFE_OpenDeviceRemote(&dev, IP, 9797, &creds)`，
其余调用一行不改。客户端构建：`sh board/demo/build_client.sh`。
凭据三件套 `hsm_ca.crt` / `client.crt` / `client.key`，演示用的一份在 `demo/remote/creds`。

## 四、一次实测的输出

2026-10-10，D7 位流 + D7 启动镜像（开机默认）：

```
A1  ML-KEM-768 生成 2.6 ms；私钥 dk 没有以明文出现在 TEE 之外
A2  SDFE_GenerateKey 1.3 ms → 60 字节 blob；LoadKey 1.3 ms；重装同密文 ✅ 篡改被拒 ✅ 明文导入被拒 ✅
B1  ML-KEM-768   生成 2.5 ms │ 封装 1.4 ms │ 解封装 3.5 ms
B2  ML-DSA-44    生成 2.5 ms │ 签名 11.9 ms │ 验签 1.8 ms
    ML-DSA-65    生成 3.1 ms │ 签名  6.1 ms │ 验签 2.7 ms
    ML-DSA-87    生成 4.0 ms │ 签名 17.7 ms │ 验签 3.8 ms
B3  AES/SM4 × CBC/CTR/CFB/OFB 8 组对上标准向量；AES-256-CBC 0.92 MB/s
四  会话后 VALID_MAP = 0x00；普通世界装载 11 笔全被拒，LOAD_REJ +11
```

签名时延的波动来自 ML-DSA 的拒绝采样（每次签名重试次数不同），不是测量误差。
对称吞吐的瓶颈是每次寄存器访问都要经 EL3（一次 SMC），不是 FPGA 算得慢。

完整输出与送检形态（`SECURE_ONLY=1`，普通世界连读都读不到）的证据在仓库
`board/logs/RESULT_demo_new.txt`、`RESULT_d7_*.txt`。

## 五、出问题时

| 现象 | 怎么办 |
|---|---|
| `192.168.50.174` 连不上 | 正常。装入密码位流后 `eth0` 就没了，用 `.175` |
| `.175` 也连不上 | 两个口都插了吗？串口进去看 `HSM_STATUS` |
| `READY=no` | 看 `/media/sd-mmcblk1p2/hsm/hsm-boot.log`，每一步失败都写了原因 |
| `DAEMON=nosock` 且日志说"TA 那条种子路不通" | 多半是板子掉过电又起在旧镜像上；`BOOT.BIN` 现在就是 D7，正常不会出现 |
| 远程连不上 | 时钟对吗（板子没有 RTC，证书有生效时间）？板上 `pki/` 三件套缺一就**不**监听 |
| load ≈ 1.0 但 CPU 全闲 | 正常，一个 USB 集线器内核线程常驻等待，与本项目无关 |

**重启**用 `sh /media/sd-mmcblk1p2/hsm/hsmreboot.sh`（`reboot` 命令在这块板上不生效）。

## 六、边界，说清楚

- **没有硬件信任根**：没有烧任何一次性熔丝，所以没有认证启动。能改 SD 卡的人
  可以换掉启动镜像（比如换一个会打印密钥的 OP-TEE）。"密钥在 TEE"挡的是普通世界
  的软件攻击，**挡不住能改镜像的人**。
- **KEK 的根可推导**：TA 的 KEK 派生自 SHA-256(Device DNA)，而 DNA 可读。
  在这块板上，blob 对"能读 DNA 又拿到 blob"的人不是真正的密文。真 HUK 依赖认证启动。
- **远程口**：mTLS 有了传输加密与身份，但没有权限分级与吊销；仓库里的演示凭据是公开的。
- **PKCS#11**：设 `PQCHSM_BACKEND=sdfe` 时 ML-KEM 走这台密码机，其余机制在 PKCS#11
  侧目前仍是软件后端（瘦客户端是下一步）。
- **任何能打开 TA 会话的本地进程**都能让 TA 往产品槽装一把它自己 blob 里的密钥
  （拿不到明文，但能占槽）。按身份授权是下一步。
