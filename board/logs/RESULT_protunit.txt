=== ZynqMP 保护单元实配（经 EL3 只读窗口）===

[XPPU —— LPD 从机的许可表  base 0xFF980000]
  XPPU_CTRL              @0xff980000 = 0x00000000
  XPPU_ERR_STATUS1       @0xff980004 = 0x00000000
  XPPU_ERR_STATUS2       @0xff980008 = 0x00000000
  XPPU_POISON            @0xff98000c = 0x000ff9c0
  XPPU_ISR               @0xff980010 = 0x00000000
  XPPU_IMR               @0xff980014 = 0x000000ef
  XPPU_LOCK              @0xff98001c = 0x00000000

[XMPU_DDR0..5 —— 只列使能的区域]
  XMPU_DDR0 CTRL=0x0000000b POISON=0x00000000
  XMPU_DDR1 CTRL=0x0000000b POISON=0x00000000
  XMPU_DDR2 CTRL=0x0000000b POISON=0x00000000
  XMPU_DDR3 CTRL=0x0000000b POISON=0x00000000
  XMPU_DDR4 CTRL=0x0000000b POISON=0x00000000
  XMPU_DDR5 CTRL=0x0000000b POISON=0x00000000
  —— 六个实例里**没有一个使能的区域**

[XMPU_FPD  base 0xFD5D0000]
  XMPU_FPD_CTRL          @0xfd5d0000 = 0x00000007

[XMPU_OCM  base 0xFFA70000]
  XMPU_OCM_CTRL          @0xffa70000 = 0x00000003

=== 反证：非安全侧读 OP-TEE 的安全世界代码 ===
  devmem 0x60000000 = 0xAA0003F3
  devmem 0x60000004 = 0xAA0203F4
  devmem 0x60001000 = 0x14000000

============================================================================
【怎么读这份结果】
============================================================================
① XPPU_CTRL = 0 —— **XPPU 是关的**。LPD 那些从机没有许可表在管。
② 六个 XMPU_DDR 的 CTRL 都是 0xb（默认放行读 + 写 + poison 模式），
   而**一个使能的区域都没有** —— DDR 上没有任何安全/非安全隔离。
③ 于是 OP-TEE 的 core 段（设备树里 optee_core@60000000，0x1000_0000 大）
   对非安全世界是**完全敞开**的。上面那三个 devmem 读出来的是 AArch64 指令。

这一条直接影响对外口径：**在这块板上，"密钥交给 OP-TEE 保管就受保护了"
是不成立的。** 任何 root 都能读 OP-TEE 的代码和数据段。

============================================================================
【试过的修法，以及为什么停下】
============================================================================
在 BL31 里给 OP-TEE core 段配 XMPU 区域，试了两轮、每轮都真的上板启动：
  ① 六个实例 × R15，0x6000_0000-0x6FFF_FFFF，cfg=0x0F
     → 区域确实写进去了，六个实例都读回 0x0000000F；devmem 照样读得到。
  ② 一轮下三种位法各占一个 1 MB 窗口：R13 cfg=0x37 / R14 cfg=0x33 /
     R15 cfg=0x0F（都在 OP-TEE core 段内，Linux 不用这段）
     → **三个地址全部照常读得到。**

所以"R*_CONFIG 位定义猜错了"这条被排掉了。剩下的嫌疑是 APU 的非安全访问
到底经不经 XMPU_DDR，以及 R*_MASTER 写全 0 是不是被硬件当成"不匹配任何
主控"。这两条都要 UG1085 里 XMPU_DDR 的确切语义才能定，手上没有可核对的
依据，而每猜一轮要把板子停一次。**到此为止。**

⚠️ 那段不生效的 XMPU 配置**已经从 BL31 里删掉了**。留着比没有更糟：
   读代码的人会以为 DDR 受保护了，而它什么都没挡住。
