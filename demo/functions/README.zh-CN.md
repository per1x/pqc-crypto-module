# 密码机功能演示

一条命令走完一台密码机该有的管理功能：算法支持性、熵源、槽位管理、密钥管理、
备份恢复（M-of-N 门限）、安全存储。

```bash
cmake -S . -B build && cmake --build build -j
./demo/functions/run.sh
```

自带一切:临时密钥库、自己起的 daemon、用完就删。**不需要板子**,也不碰你已有
的任何东西。

## ⚠️ 这里演的是哪一个密码机

这个仓库里有两个东西,功能面完全不同:

| | 板上 `pqchsm_fpgad` | 主机侧 `pqchsmd`（本演示） |
|---|---|---|
| 槽位管理 | ❌ 它的"槽位"是 PL 金库 0-7 号,一块放对称密钥的硬件 | ✅ 状态机、标签、策略 |
| PIN / 会话 / 角色 | ❌ | ✅ SO / User、登录、失败计数 |
| 密钥库 | ❌ | ✅ AES-GCM 包裹 + KDR 派生 KEK + 全文件 MAC + epoch 防回滚 |
| 备份恢复 | ❌ | ✅ M-of-N Shamir 分片 |
| 密码运算 | ✅ 全在 FPGA 里 | 走 liboqs,或转发给板子 |

**槽位/备份/安全存储这些管理功能都在主机侧。** 板子那半在
[demo/remote/](../remote/) 与 [board/demo/](../../board/demo/)。

两边能接起来 —— 设 `PQCHSM_BACKEND=sdfe` 之后 ML-KEM 的密钥生成走 FPGA、私钥进
PL 片内金库,于是"槽位与备份在主机侧管、密钥材料在硬件里"。但那样有一个真实的
取舍,见下。

## 六节各证明什么

| 节 | 看点 |
|---|---|
| 一、算法支持性 | `C_GetMechanismList` + `C_GetMechanismInfo` —— **问模块自己**,不是问文档。两者不一致时这里说了算 |
| 二、熵源 | 主机侧的随机数来自 OpenSSL,**不是** PL 熵源。硬件熵源(8 个环振、H = 0.871)在板子上 |
| 三、槽位管理 | 列举全部槽位、状态机 `UNINIT → EMPTY → LOADED`、SO/User 两个角色。**反例:没登录就生成 → not authorized** |
| 四、密钥管理 | 生成 / 导出公钥 / 签名 / 销毁。**命令表里没有"导出私钥"这一条,这是结构性事实** |
| 五、备份恢复 | 策略位决定能不能备;2-of-3 门限。**反例:只给 1 片必须失败**;换一组分片仍然成功,说明是真门限 |
| 六、安全存储 | **反例甲**:改坏 1 bit → 拒绝装载**且不写盘**。**反例乙**:旧快照回放 → 被 epoch 锚点拒绝 |
| 七、算法调用 | 支持不等于能用。签名类走完 `C_GenerateKeyPair → C_Sign → C_Verify`,**改消息一个 bit、改签名一个 bit 各验一次,都必须失败**;KEM 类走完封装 → 解封装 → AES-GCM(KEM-DEM),并演私钥导出被拒 |

反例才是重点。一台密码机是被它**拒绝**什么定义的,不是被它算出什么定义的。

## 两个容易读反的地方

**`backup` 的 `<slot>` 参数不是"备份哪个槽"**,而是**用哪个槽位的 SO PIN 来授权**。
导出的是密钥库里所有带 `BACKUPABLE` 策略的槽位。`pqchsm-admin` 的帮助串这里写得
有歧义。

**"能备份"和"留在硬件里"是互斥的。** 备份备的是种子,而私钥一旦进了 FPGA 的片内
金库就没有读出路径,也就没法备份。可恢复 ↔ 不可导出,只能选一个 —— 这不是缺陷,
是必须由使用者做的决定。

## 环境变量

`BUILD=`(默认 `build`)、`PORT=`(默认 19099)、`SO_PIN=`、`USER_PIN=`。
