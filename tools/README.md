# tools/

Development and verification scripts. The regression and analysis scripts run on
the development host. The scripts under "Board and remote use" need a board or
the address of one.

## Regression

| Script | What it does |
|---|---|
| `rtl_sim_fast.sh` | RTL edit loop: per-module cocotb testbenches under Verilator, minutes instead of tens of minutes. Verilator is two-valued and does not propagate X, so it does not replace the full suite |
| `rtl_sim.sh` | The full cocotb suite under Icarus Verilog (about 40 minutes), run before merging. Generates the golden vectors on first run (`hardware/model/export_vectors.py`) |
| `rtl_lint.sh` | Verilator `-Wall` plus Icarus syntax check, each module as its own top level; no warnings allowed |
| `rtl_synth_check.sh` | Yosys synthesisability check for every module |
| `aarch64_test.sh` | Full rebuild and host regression inside an aarch64 Linux container |
| `fuzz.sh` | libFuzzer targets (needs Homebrew LLVM clang; skipped if missing) |
| `e2e_p11.sh`, `p11_smoke.sh`, `demo_p11.sh`, `cli_smoke.sh` | PKCS#11 and CLI end-to-end checks. `p11_smoke.sh` compares `pkcs11-tool` behaviour with SoftHSMv2 |
| `daemon_failclosed.sh` | `pqchsmd` must fail closed: if the keystore fails to load it must not serve an empty token or overwrite the real keystore on exit |
| `tls_regress.sh` | mTLS regression for the remote port (right CA, wrong CA, no certificate, CN not in the ACL) using a throw-away PKI; no board needed |
| `tee_native_tests.sh` | Builds and runs `tee/tests` on the host (TA-side primitives compared with the normal-world implementation) |
| `mldsa_grid.sh` | ML-DSA gate: KeyGen, Sign, Verify and AXI for 44, 65 and 87, each against the ACVP vectors |
| `check_profile.sh` | A PRODUCTION build must not contain the stub root-key literal |
| `check_ta_surface.py` | The removed TA oracle commands must stay removed (`--self-test` runs only the built-in self-check) |
| `check_atf_patch.py` | Compiles the C fragments generated by `boot/atf/patch_atf_secmmio.py` on the host |
| `check_shell_vars.py` | Rejects `$VAR` directly followed by a multi-byte character in shell scripts |
| `kat_evidence.sh` | Regenerates the KAT evidence table by running `kat_runner` |

## Analysis

| Script | What it does |
|---|---|
| `sp800_90b.py` | The SP 800-90B non-IID min-entropy estimators. `--selftest` reproduces the examples from the specification |
| `restart_test.py` | SP 800-90B section 3.1.4.3 restart test |
| `ct_audit.py` | Constant-time source audit (`--self-test` checks the scanner on synthetic samples) |
| `check_zeroize.py` | Checks that structs holding key material are cleared by their destroy functions and that local key buffers are cleared on every return (`--self-test`) |
| `check_no_readback.py` | Checks that the public headers declare no function that reads out the key derivation root |
| `cycle_budget.py`, `prim_count.py`, `amdahl.py` | NTT cycle budget, Keccak/NTT call counts per ML-KEM operation, and speed-up estimates for hardware partitioning |
| `profile.sh` | Sampling profile of `pqchsm-bench` using macOS `sample(1)` |

## Board and remote use

| Script | What it does |
|---|---|
| `mkpki.sh` | Generates the device PKI for the mTLS remote port on the host, so the CA private key stays off the board |
| `demo_remote.sh` | Runs the board demo from a host over mTLS: `<IP> --provision` (install credentials, once), `--smoke`, `--status` |
| `dna_bind_check.c` (CMake target `dna-bind-check`) | Checks device-bound key derivation, locally or against a remote board over mTLS |

## Support

| File | What it does |
|---|---|
| `fetch_vectors.sh` | Downloads and flattens the NIST ACVP vectors, pinned to a specific ACVP-Server commit |
| `acvp_to_kat.py` | Converts ACVP JSON into the KAT format the tests read |
| `mldsa_kat_to_c.py` | Converts ACVP ML-DSA vectors into the C header used by the on-board test (`board/src/kat_mldsa.h`) |
| `demo_to_html.py` | Converts the board business-demo output into a standalone HTML report |
| `bench.c`, `prim_bench.c` | Benchmark sources built by CMake (`pqchsm-bench`, `pqchsm-prim-bench`) |
| `pdf/` | Builds the design-and-validation reference PDF from the Chinese docs (pandoc and headless Chrome) |
| `fsbl_xmpu/` | Draft FSBL code that configures the DDR XMPU. Not tested on a board and not used; the BL31 patch configures the DDR XMPU now. See [../docs/SECURITY.md](../docs/SECURITY.md#memory-isolation-on-ddr-xmpu) |
