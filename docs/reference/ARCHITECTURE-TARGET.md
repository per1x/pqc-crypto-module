# 最终目标架构（PQC 密码机 / ALINX AXU3EGB）

> 状态：设计文档，非"已实现"清单。凡与仓库代码有出入处，本文以代码/RTL 为准并显式标注。
> **本版按既定路线定架构：密钥与密钥种子的权威保管在 PS 的 TEE（OP-TEE 安全世界），
> TEE 是当前主线、必需，不是可选项；PL（FPGA）退回纯计算角色，只存多项式/公开参数、只做运算；
> 种子由 TEE 经安全世界通路送入 PL 展开成完整密钥参与运算，长期机密始终归 TEE 保管。**
>
> 但这条路线在**本项目当前形态**下有几个硬问题（按红线不烧 eFUSE→安全启动与秘密根未启用、
> 未供给形态下 HUK 退化为 DNA 派生、种子跨 AXI、每次重展开的性能代价、OP-TEE 未上板）。
> §7 把这些当作"代价与前提"老实写，并给出诚实结论：**这条路线有条件成立**——它是 CODE-1 运行时
> 威胁的正解，但**在不烧 eFUSE 的形态下**换不来"抗离线/JTAG 窃取"的硬保管，别按后者宣称。
>
> **归因纪律（本文全篇遵守）**：凡"没有 X"必须归因到最窄的真实主语，分四类——
> **(a)** 硅具备、本项目选择不启用（eFUSE 全套：`PPK*_HASH`/`RSA_EN`/`ENC_ONLY`/`FUSE_AES`/PUF/`USER_0…7`）；
> **(b)** 这块 AXU3EGB 板卡缺的硬件（`VCC_PSBATT` 无电池，量产载板上消失）；
> **(c)** 需新增产品硬件（防篡改传感器/网格）；**(d)** 成因未定位的实测失败（PUF 黑钥）。
> 红线的准确定义见 `SECURITY.md` L35-36：**不可逆动作需板主显式同意、默认答案是不**——一条可推翻的
> 默认拒绝，不是物理不可能。故本文不用"永久排除/做不成/本板补不了"。
> 量产要把信任根真正立起来具体需要什么，见 [HSM-COMPARISON.md §4](HSM-COMPARISON.md)。
>
> 硬件平台 ZU3EG MPSoC：PS（4×Cortex-A53）+ PL（FPGA）。

## 0. 术语与命名（本文钉死，其余文档名称不一，引用时以此为准）

| 概念 | 本文用词 | 说明 |
|---|---|---|
| `SECURE_ONLY=0` 位流 | **演示形态** `zu3eg_hsm_dev.bit` | 上电默认；普通世界经 `/dev/mem` 可直接驱动核 |
| `SECURE_ONLY=1` 位流 | **安全形态** `zu3eg_hsm.bit` | 交付/送检；普通世界碰任何寄存器都被 RAZ/WI 拒 |
| 板上守护进程 | **硬件面 daemon** `pqchsm_fpgad` | 目标形态里退化为 TA 的普通世界 RPC 转发器（见 §5） |
| 主机/板上管理进程 | **管理面 daemon** `pqchsmd` | 槽位 FSM / 角色 / PIN / 备份 / 审计（策略，不碰密钥值） |
| 安全世界应用 | **TA**（OP-TEE Trusted Application，S-EL1） | 目标形态里密钥/种子的权威保管者与运算编排者 |
| 安全监视器 | **BL31 / EL3** | 唯一能签发安全（`AxPROT[1]=0`）事务、能区分调用者世界的层 |
| 软件 profile | **DEV / PRODUCTION** | `cmake -DPQC_PROFILE=`；与位流形态正交，见 §6 |

**四类归属**贯穿全文：**PL**（FPGA 逻辑）、**PS-普通世界**（EL0/EL1 Linux）、
**PS-TEE**（S-EL1 / OP-TEE，权威保管在此）、**PS-EL3/BL31**（安全监视器，通路守门）。

**本版与上一版的根本区别**：上一版把私钥/种子的物理保管收在 **PL**（种子在 PL 内自生、永不跨 AXI），
TEE 写成可选。本版按用户既定路线**反过来**：权威保管收在 **PS-TEE**，PL 退回无状态计算，种子经
安全世界通路跨 AXI 进 PL 展开。两版的威胁模型收益不同，§3/§7 讲清各自到什么程度。

## 1. PS / PL / TEE / 普通世界 —— 归属逐项定清楚（TEE 主线版）

"现状"= 代码里实际的样子；"目标"= 本路线要收敛到哪里；"理由"= 信任与性能依据。

| 项目 | 现状归属 | 目标归属 | 理由（信任 / 性能） |
|---|---|---|---|
| **密钥种子**（ML-KEM `d‖z` / ML-DSA `ξ`） | PS-普通世界（daemon 栈，CODE-1） | **PS-TEE（权威保管）** | 种子=长期机密，完全决定私钥。收进 S-EL1 后普通世界内核/root 运行时读不到（地址空间隔离 + XMPU 毒化 DDR 碳出）。这是本路线的核心。 |
| **私钥**（`dk`/`sk` 完整密钥） | PL 金库 BRAM（16/8 槽） | **不持久化任何地方**：TEE 持种子，PL 按操作从种子重展开，**算完由硬件无条件擦除** | "长期机密只有种子"是本路线的立论。PL 不再存密钥→无金库读路径可攻，也无跨操作驻留态。⚠️ "无条件"是关键词：擦除由硬件在 S_FIN/DONE 触发，**不由任何软件（包括 TA）决定** —— 会话级缓存那条折中已撤销，理由见 §7.3。代价见 §7.3（每次重展开）。 |
| 密码运算核（ML-KEM/ML-DSA/AES/SM4/SM3/Keccak/NTT/采样） | PL（整核，自带金库+种子输入） | **PL（纯计算，无状态）** | PL 保留"从种子展开→运算→出结果"的整操作能力，但不再保管密钥。运算物理隔离、常时（AES 仅周期常时，无 DPA 掩码，如实标）。 |
| **种子→PL 的传输通路** | 普通世界 daemon 直接写 `MK_INDATA`（CODE-1） | **安全世界通路**：TA → EL3 SiP（**仅安全调用者**）→ PL，走 `AxPROT[1]=0` | 见 §4。要害是 EL3 在 SMC 入口能区分调用者世界，把种子写口做成"非安全调用者拒绝"，root 便无法驱动种子输入寄存器。 |
| PL 侧计算中间态（展开后的 s1/s2/t0、A 矩阵、多项式银行） | PL BRAM，受 SECURE_ONLY 防火墙 | **不变（PL BRAM + SECURE_ONLY）** | 展开后的密钥态在 PL 内、安全形态下普通世界读回 RAZ；`DEBUG_BANK`/`ext_*` 调试口已 tie-off。中间态防泄靠同一道 AXI 防火墙。 |
| KDR / 设备派生根 | PS-普通世界（`src/crypto/kdr*.c`） | **PS-TEE**（TA 内经 system PTA 派生） | TA 用 `PTA_SYSTEM_DERIVE_TA_UNIQUE_KEY` 得 KDR。**在当前未供给形态下** HUK 退化为 `SHA-256(DNA)`、DNA 可读，故 KDR 不是真机密——按"防克隆非防读"定级。这是**形态属性不是硅属性**：供给到位后 HUK 走 CSU AES-GCM + device key。见 §7.1。 |
| keystore / 种子密文的权威保管 | PS-普通世界文件（SD ext4，KEK 包裹） | **PS-TEE 安全存储**（RPMB-FS / REE-FS，KEK 从 KDR） | 权威副本进 TEE 安全存储。**注意**：REE-FS 加密根 = HUK = DNA 派生；RPMB-FS 需 RPMB 密钥（曾误烧、现找回，provision 编译期关）。保密强度上限仍是 DNA，见 §7.1。 |
| KEK / K_file / K_meta / pin_key | PS-普通世界（从 KDR 现推） | **PS-TEE** | 派生边界正好落在 `include/pqchsm/wrap.h` / `pqc.h`——把 wrap/unwrap/派生搬进 TA 是"顺着现有接口切一刀"，不是重写。 |
| BEK / RMK（备份密钥） | PS-普通世界（RMK 导出时随机、不落盘） | **PS-TEE** | BEK 从 RMK 派生、故意不绑 KDR（备份要能跨设备恢复）。搬进 TA 后 RMK 也只在 S-EL1 内存在。 |
| SDF / PKCS#11 服务层 | PS-普通世界 | **PS-普通世界（前端）** | 会话/对象/ACL 模型不碰密钥值，留普通世界。它对密钥的每个动作变成对 TA 的一次调用。 |
| 硬件面 daemon `pqchsm_fpgad` | PS-普通世界（root，直驱 PL） | **PS-普通世界，退化为 TA 的 RPC 转发器** | 目标形态里它不再自己碰种子/PL，只把 SDF/P11 请求转给 TA。所有触碰密钥的编排在 TA 内。 |
| 管理面 daemon `pqchsmd` | PS-普通世界 | **不变** | 槽位/PIN/备份/审计是策略与状态机，不持有密钥值；PIN 验证子仍 `KMAC256(pin_key,…)`，pin_key 由 TA 保管。 |
| 审计日志 | PS-普通世界文件（现正式路径没接） | **PS-普通世界文件 + TA 签名锚** | SHA3 哈希链无密钥，真正的完整性锚是 ML-DSA 签名——签名私钥进 TA。**当前根本没 attach**，见 §9 发现。 |
| 备份分片（Shamir M-of-N） | 外部离线保管 | **不变**（切片在 TA 内做） | GF(256) 常时；分片校验和不带密钥（只防损坏），兜底是备份文件 GCM/KMAC 标签。 |
| mTLS 证书与设备私钥 | PS-普通世界文件（SD `hsm_device.key` 0600） | **PS-TEE（可选，推荐）** | 现为 0600 文件。搬进 TA 后 TLS 私钥运算在 S-EL1；但同样受 DNA-HUK 上限约束，且远程口真边界仍是 §4 的通路。 |
| EL3 SiP 通路守门 | PS-EL3/BL31（不认调用者世界） | **PS-EL3/BL31（种子写口仅安全调用者）** | 本路线成立的关键改动，见 §4.3。 |
| XMPU DDR 毒化 | PS-EL3/BL31（开机配区域 15 + 毒化） | **不变，且现在保护 TEE 侧种子** | XMPU 毒化 OP-TEE 碳出（`0x6000_0000`），挡普通世界**读** TEE DDR——正好保护种子在 TEE 侧的静态。只挡读不挡用，且只 BL31 在 EL3 能写。 |

**一句话总览**：长期机密（种子/KDR/KEK/pin_key）收进 **PS-TEE**；PL 退回**无状态计算**，按操作从
种子重展开、算完即弃；种子经 **EL3 仅安全调用者的 SiP** 跨 AXI 进 PL；三段各由三种机制守
（TEE 侧靠 XMPU+地址空间隔离，通路靠 EL3 世界区分，PL 侧靠 SECURE_ONLY 防火墙）。

## 2. PL 侧存储角色的转变（从"金库"到"无状态计算"）

上一版讲"三个金库"，本路线把它们的定位改了：

| PL 存储 | 现状 | 本路线目标 |
|---|---|---|
| ML-KEM `dk` 金库（16 槽 BRAM） | 跨操作保管私钥 | **降级为单操作内的临时展开区**，或整体不用（种子每次重送） |
| ML-DSA `sk` 金库（8 槽 BRAM） | 同上 | 同上 |
| 对称 `key_vault`（8 槽寄存器） | 保管对称密钥（无读路径） | **可保留**：对称密钥本就短小，能作为 TA 注入的临时密钥容器；但权威副本在 TA |

要写进架构的两点：

1. **PL 不再是密钥的权威保管者**，只是"给它种子它就能算"的无状态引擎。金库的单向闩
   （`dk_lock`/`sk_lock`）在本路线里不再是"锁住导出方向"的主防线（因为根本不跨操作存密钥），
   但**仍应保留**：它是"这次运算的展开态没从 `OUT_DATA` 漏出去"的软件侧自证（`n==pk_len` 断言）。
2. **⚠ 不能把"PL 退回纯加速器"理解成"改用 `pqc_accel_axi`"。** 仓库里的 `pqc_accel_axi`
   （NTT/Keccak/SHAKE 原语加速器）**连 `awprot`/`arprot` 端口都没有，没有防火墙、没有 AxPROT 门**
   （已核 `pqc_accel_axi.v`，且它当前根本没被 board top 例化）。若照它现状做"纯加速器"，等于把
   总线级隔离整个丢掉。**本路线的无状态计算必须继续走带 `axi4lite_firewall` 的 wrapper
   （`mlkem_axi`/`mldsa_axi` 那套 SECURE_ONLY 门），或给加速器补一道同样的防火墙。** 见 §7.2。

## 3. 信任边界与威胁模型 —— 各挡到什么程度

按攻击者能力分档。**本路线相对上一版，收益集中在"运行时普通世界 root"这一档；对"离线/JTAG"
这一档没有实质提升**——这是最必须讲清的一点，别含糊。

### 3.1 运行时普通世界 root（板上有 root，但不能改镜像重启、不能 JTAG）

| 目标 | 本路线挡住吗 | 依据 |
|---|---|---|
| 运行时读种子/私钥 | **挡住（这是本路线的主收益）** | 种子只在 S-EL1 内存与 PL BRAM 里存在；普通世界内核/root 读不到 S-EL1（地址空间隔离），读不到 PL（SECURE_ONLY RAZ），读不到 TEE DDR（XMPU 毒化）。修掉了 CODE-1 里"root 从 daemon 内存抓活种子"。 |
| 换 daemon 二进制窃取 | **挡住** | 触碰密钥的编排在 TA 内；换普通世界 daemon 只换到 RPC 转发器，拿不到种子。修掉 CODE-1 的"换二进制"路径。 |
| 直接开 `/dev/secmmio` 驱动种子输入寄存器 | **挡住（依赖 §4.3 改动）** | 种子写口 SiP 做成仅安全调用者；root 的 SMC 带非安全态，EL3 拒。**没有 §4.3 这条改动，本路线不成立**——root 照样能自己驱动 `MK_INDATA`。 |
| 用私钥（签名/解封谕言机） | **部分挡** | 编排进 TA 后，普通世界要用密钥只能经 TA 调用，TA 可加 PIN/会话门控。但只要 TA 暴露 SIGN/DECAPS 命令，被攻陷的普通世界仍可把 TA 当谕言机（TA 头自认"防普通世界应用，不防普通世界内核"）。 |

### 3.2 离线攻击者（拿到 SD 卡 / 能 JTAG）

| 目标 | 本路线挡住吗 | 依据 |
|---|---|---|
| 从 TEE 安全存储取种子 | **在当前未供给形态下，挡不住到"硬件保护"的程度** | REE-FS 加密根 = HUK；**未供给形态下**上游 `zynqmp_huk.c` 见 CSU STATUS 的 AUTH 位为 0 会静默降级成 development HUK = 纯 `SHA-256(DNA)`，DNA 从 EL1 经 SMC 可读→根不是机密。**强度等同今天的 DNA 包裹 keystore**，见 §7.1。 |
| 替换 OP-TEE 本身 | **挡不住** | 本项目按红线未烧 eFUSE→安全启动未启用，BOOT.BIN（含 BL32=OP-TEE）的认证**不锚在 eFUSE**。攻击者把 SD 上的 OP-TEE 换成"打印出密钥"的恶意 BL32，板子照跑。**"密钥在 TEE"对能改镜像的人不提供任何保密。** |

> **机械精度 vs 安全结论，两件事别混**：严格说不是"没有任何认证"——本项目记录过零 eFUSE 的 RSA 认证
> 启动可跑；准确表述是**认证不锚在 eFUSE**。但 `bh_auth_enable` 按定义就是"跳过 PPK 摘要校验"，
> 所以它对"攻击者换镜像"提供的保护是**零，不是部分**。归因可以软化，安全结论一个字都不能软。
> （另注：这条唯一的肯定结论在仓库内**无脚本可复现**，且原实验**对它自己声称的性质没有鉴别力**
> ——`RSA_EN` 未烧时 BootROM 是否认证只取决于启动头 `bh_auth` 位，而 bootgen 对拼错属性静默忽略，
> 于是"认证通过"与"认证被静默跳过"两种情况下的全部可观测量逐字相同。证据与所缺的两个阴性对照见
> [`boot/persist/RSA-AUTH-BOOT-NOTE.zh-CN.md`](../../boot/persist/RSA-AUTH-BOOT-NOTE.zh-CN.md)。）

**结论先行**：本路线把保护从"运行时"这一维做实了，但**本项目在现行红线下不做实**"离线/JTAG"这一维
——那需要烧 eFUSE 建立信任根，落在红线之内（红线是可经板主同意推翻的默认拒绝，且其理由"只有一块板"
在量产时自动失效）。所以本架构文档必须按"运行时隔离 + 设备绑定"宣称，**不得**写成"密钥受硬件保护的
安全存储"。后者会重演项目已经点名的 DOC-2 错误（HUK"不出芯片"）。

### 3.3 回滚 / 跨设备 / 物理

- 回滚：keystore `epoch` 挡"换单个旧文件"；默认文件锚挡不住"两个文件一起回滚"；**目标用 RPMB 写计数器**
  （board/src 已有帧层，src/ provider 未接）。备份 blob **无 epoch=可重放**，需补设备绑定 epoch。
  注意别把防回滚写得比实际绝望：除 RPMB（**红线之内、今天就能做**）外，硅上还有 `USER_0…7` 可做单调
  计数（(a) 类量产项）。这是"没做"，不是"不能做"。
- 跨设备：KEK 绑 DNA→挡克隆；备份 BEK 不绑=有意可迁移。
- 物理/JTAG：**当前形态基本不设防**。tamper（OT 过温）在 RTL 里有通路但从未物理触发过（需 125 ℃）。
  归类为 **(c) 需新增产品硬件**（网格/光电/电压毛刺传感器），与信任根的 (a) 类性质不同——但也别写成
  最难：RTL 的 tamper 输入与金库清零通路已经在，缺的是 BOM + 机械 + 一次台架验证，是采购与工程，
  三项缺口里**未知数最少**。

## 4. 种子托管与安全 AXI 通路（本路线的 CODE-1 正解）

### 4.1 与上一版的区别

上一版正解：种子**生成于 PL、永不跨 AXI**。本路线正解：种子**由 TEE 保管，经安全世界通路跨 AXI
进 PL 展开**。两者都能修掉 CODE-1（"别让种子过普通世界"），但机制不同：

- 上一版靠"种子根本不进 PS"——边界是地址译码物理事实，对任何 PS 侧攻击者都硬。
- 本路线靠"种子只走安全世界，普通世界看不见这条 AXI 事务，且驱动它的 SiP 拒非安全调用者"。

### 4.2 种子跨 AXI 为什么普通世界拿不到

一次操作的通路：
```
TA(S-EL1, 持种子) → EL3 SiP(仅安全调用者) → PL 内部 AXI fabric → MK_INDATA/xi 寄存器 → 核内展开
```
三重保证，逐条说清：

1. **传输在途不可见**：种子字节走 PS `M_AXI_HPM0_LPD` → xbar → 从机的**片内 AXI fabric**，
   普通世界无法旁路侦听内部布线。落点是 PL 寄存器，安全形态下普通世界读回 RAZ。
2. **普通世界签不出安全事务**：SECURE_ONLY=1 防火墙要求 `AxPROT[1]=0`。只有 EL3/安全世界能产生
   `AxPROT[1]=0` 的事务；普通世界 EL1 产生的事务恒 `AxPROT[1]=1`，被防火墙 RAZ/WI 拒。root 唯一能
   到 PL 的路只有经 EL3 SiP。
3. **SiP 种子写口拒非安全调用者**（§4.3）：堵死"root 经 SiP 自己驱动种子输入寄存器"这条旁路。

展开后的中间态（s1/s2/t0、A 矩阵、多项式银行）留在 PL BRAM，同受 SECURE_ONLY 防火墙；调试口
`DEBUG_BANK`/`sha3_core.ext_*` 已在例化处 tie-off。算完即弃（复位/下次操作覆盖）。

### 4.3 关键改动：EL3 SiP 按调用者世界分级

这是本路线成立与否的**单点前提**。当前 `/dev/secmmio` 的 SiP（`PL_RD 0x8200ff12`/`PL_WR 0x8200ff13`）
**不认调用者**——它同样服务普通世界 root（`docs/SECURITY.md:203-207` 自认）。若不改，TEE 保管种子
毫无意义：root 照样能 `PL_WR` 到 `MK_INDATA`。

好消息：**SMC 陷入 EL3 时，EL3 能从进入态读到调用者是安全世界还是普通世界**（`SCR_EL3.NS`）。所以
BL31 侧的小改动是：

- 新增一个**仅安全调用者**的种子装载 SiP（或给现有 `PL_WR` 加"目标地址落在种子输入寄存器
  窗口时，要求调用者为安全世界"的判定）。非安全调用者写种子口→拒。
- 普通世界仍可经原 SiP 做非机密操作（或干脆全部经 TA，见 §5，那样 SiP 可整体收成仅安全调用者）。

这条改动约几十行 BL31 逻辑，且**复用已在板上验证过的 EL3 安全事务签发**（secmmio 路径已跑通），
是本路线里风险最低的一环。**没有它，本路线在 root 面前等于零。**

### 4.4 仍需软件侧收口（无论走哪版都要做）

消灭第二条种子路径：安全 profile 禁用 `SEED_STORAGE`（否则种子落盘进 keystore）；非演示构建强制
device-dna KDR，禁 stub 公开常量根；修 ML-KEM 失败路径 `seed[]` 未清零、`session_end` 不清
`pay`/`out` 静态缓冲（`DECAPS` 的 32 字节 `ss` 残留）；`pqc_random_bytes` 硬件源判定从
`hwrng_available()`（stub 也真）改 `hwrng_is_hardware()`。

## 5. 关键数据流（TEE 主线版）

命名：**A**=应用，**P11/SDF**=普通世界前端，**Fd**=退化的转发器，**TA**=安全世界应用，**PL**=FPGA。

### 5.1 KeyGen
```
A → P11/SDF → Fd → TA(S-EL1)
TA：从熵源生成种子 d‖z/ξ → 存进 TEE 安全存储（权威副本）→ 经 §4.3 安全 SiP 送种子入 PL
PL：从种子展开 → 算 pk（及 KeyGen 内部产物）→ 只回 pk
返回：pk + 一个 TA 侧句柄（指向 TEE 里的种子）。私钥/种子不出安全世界。
```

### 5.2 Sign / Decaps（每次从种子重展开）
```
A → … → TA：句柄 → 从 TEE 安全存储取种子 → 经安全 SiP 送入 PL
PL：从种子重展开完整密钥 → 运算（ML-DSA hedged sign / ML-KEM decaps 含隐式拒绝）→ 出结果
返回：签名 / 共享密钥 ss。展开态算完即弃。
⚠ 每次运算都重跑一遍"种子→完整密钥"的展开，这是本路线的主要性能代价，见 §7.3。
```

### 5.3 KEM-DEM / 备份恢复 / PIN 登录
- KEM 半在 PL，DEM（AES-256-GCM over ss）半在 TA 内（不再落普通世界 OpenSSL）。
- 备份：TA 内 RMK→BEK→Shamir 切片；restore 仍**无会话门控**（面向空白设备），需补物理恢复模式 + SO 现场授权。
- PIN：验证子 `KMAC256(pin_key,…)`，pin_key 由 TA 保管；失败计数落盘（含失败路径），≥3 锁 User，SO 只计数不锁。

## 6. 两形态在这套架构下的样子

形态是位流参数（RTL），profile 是软件编译开关，二者正交。

| | 演示形态（上电默认） | 安全形态（交付/送检） |
|---|---|---|
| 位流 | `zu3eg_hsm_dev.bit`，`SECURE_ONLY=0` | `zu3eg_hsm.bit`，`SECURE_ONLY=1` |
| 普通世界经 `/dev/mem` | 可直驱核（跑 KAT、演示） | 碰任何寄存器 RAZ/WI |
| 种子通路 | 演示可放松（普通世界直喂），仅用于功能演示 | **仅安全世界**：TA→安全 SiP→PL（§4） |
| 密钥保管 | 演示可用 PL 金库图省事 | **TEE 权威保管，PL 无状态** |
| 用途 | 开机 35 秒自动就绪的功能演示 | 边界真正成立 + 运行时隔离 |

关键不变量：安全形态 EL3 白名单**必须**含 ML-DSA 槽 6（`0x8006_0000`），否则"位流加载成功但啥都读不回"。

软件 profile：**本项目在当前红线形态下到不了 PRODUCTION**——秘密硬件根未启用（(a) 类：硅具备，
红线选择不烧 eFUSE），叠加这块 AXU3EGB 的 BBRAM 无电池（(b) 类，量产载板上消失）。注意这不只是
"烧不烧"的问题：`bbram`/`efuse`/`puf` 三个 provider **一行代码都没有**，`pqchsmd` 从不安装任何
provider，PRODUCTION 形态从未端到端构建过——详见 [HSM-COMPARISON.md §4.3](HSM-COMPARISON.md)。
目标交付 = 安全位流 + device-dna KDR + DEV profile + TEE 主线，**并按 §3/§7 的强度定级**，不冒充硬件保护。

## 7. 这条路线的代价与前提（诚实评估，用户要求"该反驳就反驳"）

### 7.1 信任根：**在不烧 eFUSE 的形态下**，"密钥存在 TEE"到底多硬？

**结论：在本项目当前（未供给）形态下，只到"运行时隔离 + 设备绑定"，到不了"硬件保护的机密存储"。
别按后者宣称。**——注意这句话的前提是"未供给"，不是"这颗硅不行"。

- OP-TEE 安全存储（REE-FS）用 HUK 派生的密钥加密。**未供给形态下**，上游 `core/drivers/zynqmp_huk.c`
  读 CSU STATUS 的 AUTH 位，为 0 就静默降级成 development HUK = 纯 `SHA-256(Device DNA)`，只打一行
  `IMSG` 日志。DNA 从 EL1 经 SMC 可读（`0xFFCA0050`）→**根不是机密**。
  **⚠️ 这里要纠正本仓库传播最广的一条归因错误**：`kdr_dna.c:16-18` 等三处写着"OP-TEE 在这颗片子上的
  HUK 也是 SHA-256(DNA)，性质完全一样"——这被写成了**这颗硅的属性**，实际是**当前未供给形态的属性**。
  供给到位后（PUF 注册或 `FUSE_AES`，且认证启动成立），HUK = `SHA-256(DNA + 选中的 USER eFUSE)` 再经
  **CSU AES-GCM 用 device key 加密**，是真正的硬件保护。
- **失败形态是"看起来跑通了"**：即便烧了 PUF/eFUSE AES，只要认证启动没同时成立，AUTH 位仍为 0、HUK 仍
  退化。这是本路线最容易被自动脑补成"配置一下就好"的地方。
- 本项目按红线未烧 eFUSE→安全启动未启用，BOOT.BIN（含 BL32=OP-TEE）的认证不锚在 eFUSE。能改 SD 的人
  可直接**替换 OP-TEE** 成恶意版本，"密钥在 TEE"对他等于不存在。
- 所以**在当前形态下**，TEE 保管对"离线/JTAG 攻击者"的强度**与今天 `KDR=device-dna` 的 DNA 包裹
  keystore 相同**：都是防克隆/设备绑定，不是防读。TEE 多给的**只有运行时**：把种子挪出普通世界可寻址
  内存，挡住运行时 root（§3.1）。这是真收益，也是 CODE-1 的正解方向；但它是运行时收益，不是保管强度收益。

**这直接反驳一种可能的预期**：如果切 TEE 是为了"让密钥抗物理/离线窃取"，那**本项目在现行红线下不做这件事**
——需要的是烧 eFUSE 建立信任根（`PPK0_HASH + RSA_EN` 给防替换认证根，`FUSE_AES` 或 PUF 给秘密派生根，
**这是两件独立的事**）。若目标是抗离线窃取，应明说"**本形态未启用**该能力（红线所致）"，而不是用 TEE
制造一种做到了的观感。

**同时也别滑到另一个极端。** "量产烧了 eFUSE 就有信任根"同样是失真，而且在对外文档里更危险——它承诺
交付。真实的剩余工作见 [HSM-COMPARISON.md §4](HSM-COMPARISON.md)：两套独立烧写项 + OP-TEE 供给（否则
AUTH 位那道闸门静默降级）+ 三个**一行代码都没有**的 KDR provider + 三处从没接过的装配线 + 换根后的
keystore 迁移路径 + 产线密钥保管（Bootgen HSM 模式、XLWPT 需向 AMD 索取、逐片 PUF 注册、留牺牲片）。
**上限是策略选择，不是硅的能力边界；下限是一堆没写的代码和没建的流程。两句话必须同时说。**

### 7.2 种子跨 AXI + 无状态 PL 的隔离前提

- 种子跨 AXI **不等于** CODE-1（CODE-1 是过*普通世界*；这里走*安全世界*）。但成立依赖两个前提，缺一不可：
  1. **§4.3 的 SiP 世界分级**——否则 root 经 SiP 自驱种子口，全盘落空。
  2. **无状态 PL 必须保留 SECURE_ONLY 防火墙**——不能改用仓库里那个**无 AxPROT 门**的
     `pqc_accel_axi`（§2.2 已核）。否则展开后的中间态在普通世界可读，比现状更糟。
- 展开态防泄：靠 PL 侧 SECURE_ONLY 防火墙（同现状），加调试口 tie-off（已做）。这一层不比现在弱，
  但也不比现在强——它就是现有的 PL 边界。

### 7.3 性能：每次重展开 vs 密钥常驻

- 现状（密钥常驻 PL 金库）：KeyGen 时展开一次存 BRAM，Sign/Decaps 复用，快。
- 本路线（TEE 持种子、PL 每次重展开）：每次 Sign/Decaps 要先把种子重跑一遍展开
  （ML-DSA 的 ExpandA/ExpandS、ML-KEM 的 A 矩阵采样——这些是大量 Keccak/SHAKE），**再**签名/解封。
  展开是签名成本里很大一块；**估计每次操作时延约翻倍甚至更多，主导项是重跑 ExpandA**（需上板实测，
  本文不杜撰精确周期数）。种子传输本身（32/64 字节按字节写 `IN_DATA`）相对小但非零。
- ~~**折中建议**：TA 门控的 PL 会话内缓存~~ —— **已撤销**（FINAL-PLAN D2 / PLAN-01）。

  这里原来写着"TEE 权威保管不排斥 PL 侧做一个 TA 门控的临时缓存，把展开态在一次会话内留在
  PL BRAM，只在未命中时重送种子；代价是密钥态在 PL 内短暂驻留，但它由 TA 控制生命周期"。

  **撤销的理由是它自己立不住，不是口味问题**：所谓"TA 控制生命周期"只在 TA 活着、且愿意
  发清除命令时成立。TA 崩溃、被拒服务、或者干脆掉电的时候，那条清除命令**根本发不出去**——
  于是"短暂驻留"变成"留到下一次上电为止"。也就是说这个折中只改变了**谁来清**，
  没有改变"秘密在 PL 里过夜"这个事实，而后者正是本路线要消灭的东西。

  **定**：每次运算从种子重展开，不设会话级缓存；擦除由**硬件在 S_FIN/DONE 无条件触发**，
  不由任何软件（包括 TA）决定；展开区不带 valid 位、不带跨请求可引用的槽号语义。
  吞吐不够就走 §D11 的 I/O 打包与后续优化，不靠让秘密多待一会儿来换。

### 7.4 落地现实：切主线是多大工程

- **前置死结**：OP-TEE TA **从未上板跑通**（卡在 BL32 入口，§9）。在这解决之前，整条主线是空中楼阁。
  第 0 步是让 OP-TEE 真的启动，不是写 TA 逻辑。
- 现有 `tee/ta/` 是**设计完成、原生（x86）测过、驱动的是软件 liboqs——不驱动 PL**。本路线要的
  "TA 驱动 PL 核经安全 SiP"是**新代码**，不在今天的 TA 里。需要：(a) OP-TEE 启动；(b) 安全世界 PL
  驱动（TA 经 EL3 SiP 或 S-EL1 直 MMIO）；(c) §4.3 的 SiP 世界分级；(d) 种子源改从 TEE 安全存储取；
  (e) 普通世界栈改成 TA 客户端。工程量显著，且强依赖 (a)。
- 现状讽刺的一点：**今天私钥材料其实在 PL**（金库 BRAM，探读与 ACVP 都从 `board/src` 直驱 `/dev/mem`
  得到），种子才在普通世界。所以"把主线切到 TEE"某种意义上是**把保管从 PL 挪到 PS-TEE**——对
  离线攻击者是平移（都受 DNA 上限），对运行时 root 是改善（种子不再过普通世界）。

### 7.5 诚实结论

**有条件成立。** 具体：

- **若目标是修 CODE-1、挡运行时普通世界 root**：这条路线**成立且正确**，是把种子挪出普通世界的
  正解之一。前提是 §4.3（SiP 世界分级）和 §7.2（保留 SECURE_ONLY，别用无门加速器）两条硬约束都做到，
  且宣称按"运行时隔离 + 设备绑定"定级。
- **若目标是"让密钥被硬件安全地保管、抗离线/JTAG 窃取"**：这条路线**在当前未供给形态下不成立**——
  TEE 单独换不来真信任根（未烧 eFUSE→AUTH 位为 0→HUK 静默降级）。此时不建议用 TEE 制造"做到了"的
  观感；应明说"**本形态未启用**该能力"，并指出能力边界在**烧写与供给**（本项目红线内不做，量产可做，
  代价见 [HSM-COMPARISON.md §4](HSM-COMPARISON.md)），**而不是**说"这块板/这颗硅做不到"。
- **性能上**：接受重展开时延。~~或采用 TA 门控的 PL 缓存折中~~ —— 那条**已撤销**，
  理由见 §7.3（"TA 控制生命周期"在 TA 崩溃/掉电时根本不成立，它只改变谁来清）。
  吞吐先看 FINAL-PLAN D11 的 I/O 打包 —— 现在这组性能数字量的是管子，不是核。
- **相对上一版（种子在 PL 内自生）**：两版对运行时 root 收益相近；本版多一层"密钥编排在 S-EL1"
  的纵深，但多背 OP-TEE 上板这个前置死结和重展开性能代价。
  ⚠️ **这里原来建议"近期拿不到 OP-TEE 就先落 PL 内种子自生"，那条已按 FINAL-PLAN D3 撤销。**
  理由：PL 自生会让 PL 重新持有**秘密生成能力**，与"PL 无状态、只做计算"直接相悖，
  而且批 2 还得推翻重做。批 1 的正解是**把种子收进 EL3**（BL31 自己取熵、自己写进 PL 的
  种子暂存口，普通世界只发命令），批 2 再把保管从 EL3 上移到 TA ——
  **两批共用同一个 PL 侧暂存口，接口不变，只换保管者**。

## 8. 推荐形态 + 落地顺序（严守红线）

**推荐最终形态**：TEE 主线——种子/KDR/KEK 权威保管在 PS-TEE，PL 无状态计算、按操作从种子重展开，
种子经 EL3 仅安全调用者 SiP 跨 AXI；管理面（槽位/PIN/备份/审计）在普通世界软件；**按运行时隔离 +
设备绑定定级，不冒充硬件保护**。

| 批次 | 内容 | 风险 / 前提 |
|---|---|---|
| **批 0** 纯软件/文档 | 修 DOC-1..4；统一术语；接上审计日志；安全 profile 禁 `SEED_STORAGE`；强制 device-dna；修 `seed[]`/静态缓冲清零；`hwrng` 判定改 `is_hardware` | 零硬件风险 |
| **批 1** 先修 CODE-1（不依赖 OP-TEE） | 落上一版的"PL 内种子自生 + 单向仅内部闩"，或至少把种子源从普通世界 daemon 收进 EL3；先把 CODE-1 关掉 | 纯 RTL + BL31 小改；位流可运行时换、断电回黄金；**先证明能 JTAG 救援再上板** |
| **批 2** OP-TEE 上板 | 解决 BL32 入口死结，让 OP-TEE 真启动 | **本路线的前置死结**；不通则主线无从谈起 |
| **批 3** SiP 世界分级 | BL31 加"种子写口仅安全调用者"（§4.3） | 几十行；复用已验证的 EL3 安全事务签发 |
| **批 4** 编排上移 TA | KEK/wrap/私钥编排搬进 TA（边界落在 `wrap.h`/`pqc.h`）；TA 经安全 SiP 驱动 PL；普通世界栈改 TA 客户端；种子源改 TEE 安全存储 | 强依赖批 2/3；工程量最大 |
| **批 5** 防回滚 | 接 RPMB provider（provision 保持编译期关）；备份加设备绑定 epoch | RPMB 只 verify/bump，不重烧密钥 |
| **红线内不做**（本项目现行） | eFUSE 烧写、BBRAM 锁存、RPMB 密钥重烧、任何一次性闩 | 不可逆 + 会撒谎的状态读取 = 不可接受。理由是**资源与流程**（`profile.h:14-15` 自述"不可逆、只有一块板"），需板主显式同意方可推翻，**量产时此理由自动失效** |

**关于顺序的判断**：批 1 与批 2–4 是同一目标的两个阶段。**CODE-1 的修复不该等 OP-TEE**——批 1 先用
纯 RTL/BL31 手段关掉它（不依赖那个死结），OP-TEE 打通后再把编排上移到 TA 拿纵深。这样即便 OP-TEE
迟迟不上板，CODE-1 也已经修了。

### 5 个 P0

## 10. 未决 / 需上板验证（拿不准的，如实标）

- **OP-TEE TA 从未上板跑通**（卡 BL32 入口）——本路线的前置死结。现有 TA 驱动软件 liboqs、不驱动 PL；
  "TA 驱动 PL 经安全 SiP" 是新代码。
- **HUK = SHA-256(Device DNA)**：仓库内无 OP-TEE 源/补丁可复现，仅散文断言。按"据报告、不可复现"引用。
  **且这是未供给形态的属性，不是硅的属性**——上游 `zynqmp_huk.c` 在 CSU AUTH 位置起时走 CSU AES-GCM +
  device key。仓库里三处把它写成硅属性的注释需要单独修（见下）。
- **PUF 黑钥：成因未定位，不是定局。** 实测 BootROM 在触及 PUF 前拒收（`PUF_CMD=0`、`KEY_RDY=0`），
  但 `build_puf_boot.sh` 文件头自述是"变体 A（**不加 RSA**）"、bif 里没有 `bh_auth_enable`，而 XAPP1333
  说片外黑钥与辅助数据使用前**一律先过 RSA-4096 认证**；本项目又单独验证过零 eFUSE 的 RSA 认证启动可跑。
  **这两件事从没合过**，成本是一次冷启动。但即便合上跑通，**PUF 引导头模式也不足以支持
  `hardware_backed=1`**：无 eFUSE 锚定认证时，同一块板上任意镜像都能让 CSU 展开同一把 PUF KEK
  ——挡的是读，不是用。别把一次实验成功当成信任根落地。
  本路线的保密强度上限完全压在这一条上。
- **§4.3 的 SiP 世界分级**：本文断言 EL3 能从 `SCR_EL3.NS` 区分调用者世界——原理成立，但本仓库尚无
  这样的实现，需实做并上板验证"非安全调用者写种子口被拒"。
- **种子跨安全 AXI 不被普通世界侦听**：依赖内部 fabric 不可旁路 + SECURE_ONLY，原理成立，未做过针对性
  旁路测试。
- **每次重展开的性能代价**：§7.3 是估计（时延约翻倍、主导 ExpandA），需上板实测，未杜撰精确数字。
- **DNA 跨 die 唯一性未验证**（只一块板）；跨复位稳定性已验证。
- **RPMB 锚未供给**（provision 编译期关）；RPMB 读隔次返回陈帧，只按 `req_resp`+nonce 判定，不信 `result`。
- tamper→wipe 链从未物理触发；SP 800-90B 阈值绑这颗 die 与当前 DECIM。
- 本文对 RTL/防火墙/SiP 的陈述已抽样逐行核（CODE-1 两处、`pqc_accel_axi` 无 AxPROT、防火墙 permit）；
  其余引自交叉印证的探读，未逐行复核者按此标注。
