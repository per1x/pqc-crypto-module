## 2. 上板验证（板子 AXU3EGB，槽 6 的新 BL31）

### 换槽这件事绕了远路，值得记下来

`CSU_MULTI_BOOT` 在 APU 的 EL1 既读不到也写不得（写是 SError）。由此推出的
"从 Linux 没有安全路径、只剩 JTAG 与 U-Boot"是**错的** —— 忘了 PMU 可以代劳。
仓库里一直有这条路：

```
busybox insmod pmsec.ko set_multiboot=6      # 经 PMU 的 PM_MMIO_WRITE
sh hsmreboot.sh
```

`board/kmod/pmsec.c` 文件头第 24 行原文就写着。这条路走网络、不碰串口。

**判"槽 N 起来了没有"只看一件事**：回来之后 `CSU_MULTI_BOOT` 还是不是 N —— BootROM/FSBL
只在失败时自增。时间也是判据：正常 20–35 秒，≈140 秒 = 100 秒看门狗 + 落到下一槽。
两次换槽都是 31–32 秒回来、`CSU_MULTI_BOOT` 停在 6。

换之前按"槽 N 失败会落到 N+1"的纪律，把**槽 7 换成已知 10/10 能启动的镜像**当安全网，
原件备份为 `BOOT0007_prev_2d7799a3.BIN`。

### 第 6 项吞吐（`iopack_bench`，同一进程 A/B、20 次）

| 通路 | KeyGen | Encaps | Decaps |
|---|---|---|---|
| `/dev/mem` 直连 | 1.66–1.76× | 1.34–1.37× | 1.18× |
| **经 EL3（交付通路）** | **2.63–2.77×** | **2.23–2.30×** | **2.10–2.11×** |

交付通路本来就比 `/dev/mem` 慢约 2.7 倍（同样逐字节 4.56 vs 1.65 ms），多出来的
全是每字节一次系统调用 + 一次世界切换 —— 所以打包在这条路上收益更大。
Decaps 只快 1.18×（`/dev/mem`），说明它那 1.67 ms 里已有相当一部分真在算。

⚠️ **"更快"仍然不是可以对外说的话**：量的是同一块板换一种搬运方式的差值。

## 4. 本轮抓到的自身错误（都留在结果文件里）

写下来是因为它们各自代表一类**不会报错**的失败：

1. **`world != 1` 那条断言写反了。** 批 1 就是普通世界发起请求、EL3 自己取熵自己写，
   调用方是内核，`is_caller_secure()` 回 0 才对。判据随批次变，写死成 1 是错的。
2. **A/B 脚本用了这个 busybox 里不存在的 `pkill`/`pgrep`。** 两行是空操作，两轮
   连的都是开机那个旧 daemon，都 16 个 ✅、都 rc=0 —— "两轮一模一样"看起来正像
   "新旧没差别"。现在按 PID 杀 + 确认 9797 归本轮那个二进制。
3. **判据挑了 KVOK 位。** `kv_valid` 归 key_vault，而 daemon 明确写着对称金库
   **不在**会话结束时擦（应用显式 ImportKey，生命周期归调用方）。拿它当缺陷判据
   等于给正确行为判了错。
4. **打包读少了领先一拍**（mlkem）：第 1 个字节读两遍、第 3 个从没读到 —— 输出整段
   错位。是"打包与逐字节逐字节对拍"抓到的，纯计时或"能跑通"都发现不了。
5. **ML-DSA 的打包读必须多一个相位**：engine 输出口的选择器用**本拍**地址、数据是
   **上一拍**的，提前一拍会在 pk/sk 段边界稳定读错一个字节。
6. **BL31 白名单漏了新偏移**：`/dev/mem` 完全正常而经 EL3 全挂，很容易去怀疑 RTL。

## 5. 留给批 2 的

- **种子保管从 EL3 上移到 OP-TEE TA。** PL 侧**一个字都不用改** —— 暂存口的接口形状
  就是按这个设计的，换的只是"谁在写 `SEED_DATA`"。
- **`PQCHSM_SEED_NS_ALLOWED` 改成 0**。改完之后普通世界的 `SECMMIO_SEED` 会被直接拒，
  `seedel3` 里那条 `world` 断言也要跟着从 0 改成 1（用例里已注明）。
- **V-04：删掉 `dk_lock`/`sk_lock`。** 本轮刻意**没有**把 `SEED_LOCK` 与它们连动，
  就是为了不给待删的机制再焊一道。
- **D7：批量 SM4。** 本轮按方案只加擦除、没动 `sym_axi`/`key_vault` 的功能。
- **审计链的签名锚私钥移进 TA**（审计链本体留在普通世界，理由见 D10）。
- 板上时钟：板子没有 RTC，重启后回到镜像里那个日期，会让 mTLS 演示报
  `bad certificate`（证书"尚未生效"）。与本轮改动无关，但演示前要对表。
