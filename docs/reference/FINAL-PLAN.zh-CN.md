# PQC 密码机 —— 最终方案

> 决策文档。只写**定了什么、为什么、按什么顺序做**。
> 论证过程与逐项证据在 [ARCHITECTURE-TARGET.md](ARCHITECTURE-TARGET.md)（架构细节与威胁模型）
> 与 [HSM-COMPARISON.md](HSM-COMPARISON.md)（业界对比与量产路径）,本文不重复。
> 平台：ALINX AXU3EGB / ZU3EG MPSoC，PS（A53，跑 Linux + OP-TEE）+ PL（FPGA）。

---

## 1. 最终架构决定

**采用 TEE 主线**：长期机密（密钥种子及其派生根）由 **PS 的 OP-TEE 安全世界权威保管**；
**PL 只存多项式/公开参数、只做计算**；每次运算由 TEE 经**安全世界通路**把种子送进 PL，
在 PL 内展开成完整密钥参与运算，**算完即弃**。TEE 是主线、必需，不是可选项。

三段边界由三种机制各自把守：**TEE 侧**靠 S-EL1 地址空间隔离 + BL31 的 XMPU DDR 毒化；
**通路**靠 EL3 按调用者世界分级；**PL 侧**靠 `SECURE_ONLY=1` 的 AXI 防火墙（RAZ/WI）。

### 归属表

| 东西 | 放哪 | 一句话理由 |
|---|---|---|
| 密钥种子 `d‖z` / `ξ` | **PS-TEE** | 长期机密。种子完全决定私钥，故与私钥同级保护 |
| 完整私钥 `dk`/`sk` | **不持久化** | PL 按操作从种子展开、算完即弃；无跨操作驻留态可攻 |
| 密码运算核（ML-KEM/ML-DSA/Keccak/AES/SM4/SM3/NTT/采样） | **PL** | 专用数据通路，物理隔离；边界是地址译码的事实 |
| 多项式/公开参数、展开中间态 | **PL** BRAM | 受同一道 SECURE_ONLY 防火墙；调试口已 tie-off |
| TRNG（环振 + RCT/APT + Keccak 调理） | **PL** | 熵源、健康测试、调理全在片内 |
| KDR / KEK / K_file / K_meta / pin_key / RMK-BEK | **PS-TEE** | 派生边界正好落在既有 `wrap.h` / `pqc.h` 接口上 |
| keystore 密文、备份 blob | **普通世界文件** | 内容已由 TEE 包裹；放文件系统本身不是弱点 |
| 种子传输通路守门 | **EL3 / BL31** | 唯一能区分调用者世界、且普通世界改不了的层 |
| XMPU DDR 毒化（护 TEE 内存） | **EL3 / BL31** | 只 BL31 在 EL3 能写；挡读不挡用，如实定级 |
| SDF / PKCS#11 前端 | **普通世界** | 不碰密钥值，只发起对 TA 的调用 |
| 槽位 FSM / 角色 / PIN / 备份 / 审计策略 | **普通世界** | 是策略与状态机，靠密码学而非隔离保护 |
| 硬件面 daemon `pqchsm_fpgad` | **普通世界** | 退化为 TA 的 RPC 转发器，自己不碰种子与 PL |
| mTLS 设备私钥 | **PS-TEE**（目标） | 现为 SD 上 0600 文件；搬进 TA 后签名在 S-EL1 内 |
| 防回滚锚 | **eMMC RPMB 写计数器** | 计数器推得上去、拉不下来；红线之内、今天就能做 |

## 2. 需要拍板的决策点

每条格式：**业界怎么做 → 我们的处境 → 定。**

### D1 · 密钥保管：专用安全芯片 vs FPGA + TEE
业界（Thales Luna、YubiHSM 2、Marvell LS2、国密三级机）一律用**认证过的防篡改专用安全处理器**，
密钥全生命周期不出该芯片。我们这块 MPSoC **没有专用 SE**，也不打算外挂。
**定**：采用 **PL 边界 + PS-TEE** 的分工——PL 提供物理隔离的运算通路，TEE 提供机密的权威保管。
这不是"更好的 SE"，是在无 SE 平台上能做到的最强组合，宣称时按 §3 口径定级。

### D2 · 种子每次重展开 vs 密钥常驻 PL
业界的专用 HSM 把密钥常驻在安全芯片内，用的时候直接取——因为芯片本身就是保管边界，没有"要不要
搬进来"的问题。我们的保管边界在 TEE，PL 是外部计算单元，就出现了这个取舍。
**定**：**默认每次从种子重展开**（保管形态更干净，PL 内无跨操作密钥态）。
代价是每次 Sign/Decaps 要多跑一遍 ExpandA/ExpandS，**估计时延约翻倍，需上板实测,不杜撰数字**。
**允许一个折中**：TA 门控的 PL 会话内缓存——展开态在一次会话内留在 PL BRAM，由 TA 控制生命周期。
高吞吐场景走这条，严格保管场景关掉它。

### D3 · 种子跨 AXI 的通路守门（**主线成立的单点前提**）
业界无此问题（密钥不出芯片，不存在跨总线送种子）。我们把种子从 TEE 送进 PL，必须证明普通世界拿不到。
现状是 `/dev/secmmio` 的 SiP **不认调用者**——它同样服务普通世界 root。
**定**：**BL31 增加按调用者世界分级**——种子写口的 SiP 要求调用者为安全世界（`SCR_EL3.NS`），
非安全调用者一律拒。约几十行，复用已在板上验证过的 EL3 安全事务签发。
⚠️ **没有这条改动，"密钥存 TEE"在 root 面前等于零**——root 照样能自己驱动 `MK_INDATA`。

### D4 · PL 侧用哪套 wrapper（**一个真实陷阱**）
"PL 退回纯计算"**不等于**改用仓库里那个 `pqc_accel_axi`（NTT/Keccak 原语加速器）——已核实它
**连 `awprot`/`arprot` 端口都没有，没有防火墙、没有 AxPROT 门**，且当前根本没被例化。
**定**：无状态计算**必须继续走带 `axi4lite_firewall` 的 SECURE_ONLY wrapper**
（`mlkem_axi`/`mldsa_axi` 那套）；若将来启用加速器，必须先给它补同一道防火墙。
用错这一步，展开态在普通世界可读，**比现状更糟**。

### D5 · 硬件信任根
业界靠 **eFUSE/OTP 锚 + 安全启动**（PPK 摘要 + RSA_EN），这是 HSM 之为 HSM 的地基。
我们这颗 ZU3EG **完整具备**这套能力，但**本项目红线不做任何不可逆烧写**（理由：不可逆 + 只有一块板），
故未启用；这块板的 BBRAM 另无电池。
**定**：**接受为已知边界，明确记录，不粉饰也不甩锅硬件。** 具体口径：
- ✅ 可以说：本形态**未启用**秘密硬件根（红线所致），提供**运行时隔离 + 设备绑定/防克隆**。
- ❌ 不可以说："这颗硅做不到"（不实），也不可以说"密钥受硬件保护的安全存储"（夸大）。
- ⚠️ 同样不可以说"量产烧个 eFUSE 就有了"——那是另一种失真。**启动认证根与秘密派生根是两件事**，
  且 OP-TEE 侧有一道会**静默降级**的闸门（CSU AUTH 位为 0 时 HUK 退化成 `SHA-256(DNA)`，
  失败形态是"看起来跑通了"）。量产真实清单见 [HSM-COMPARISON.md §4](HSM-COMPARISON.md)。

### D6 · 物理防篡改 与 认证资质
业界必备：防篡改网格/传感器/主动清零；FIPS 140-3 L3 或国密二/三级。我们两样都没有。
**定**：**标为"产品化前置"，不塞进原型范围。** 但要如实记两点区别：
防篡改属"需新增 BOM + 机械 + 一次台架验证"，**是三项缺口里未知数最少的**（RTL 的 tamper 输入与
金库清零通路已经在）；资质是流程/时间/第三方，**下游于**前两项，且素材侧已有实体
（security-policy 草稿、ACVP 证据、缺口表），不是零起点。

### D7 · 算法广度：要不要补 RSA/ECC/SM2
业界产品传统算法全谱，靠它做现网 TLS 卸载与签名；PQC 是最近才加进固件的增量。
我们相反：PQC 全参数集硬核已硅上验证，传统算法几乎空白。
**定**：**不补 RSA/ECC/SM2，保持 PQC 专用定位。** 补了也在传统算法上毫无胜算（对方 100,000 ECC/s
量级），反而稀释唯一的差异化。定位是"PQC 硬件核"，不是"通用密码机"。

### D8 · CODE-1 的修复要不要等 OP-TEE
OP-TEE TA **从未在这块板上跑通**（卡 BL32 入口），这是 TEE 主线的前置死结。
而 CODE-1（种子经普通世界 daemon 栈，root 可抓取或替换）是当前**最实的运行时缺陷**。
**定**：**不等。** 批 1 用纯 RTL/BL31 手段先把 CODE-1 关掉（见 §3），OP-TEE 打通后再把编排上移 TA。
两者不互斥，是同一目标的两个阶段；即便 OP-TEE 迟迟不上板，CODE-1 也已经修了。

### D9 · 审计日志
业界 HSM 的审计是认证必查项。我们的审计模块写得不错（SHA3 哈希链 + ML-DSA 签名锚），
**但在正式路径上根本没接**——`hsm_token_attach_audit` 只在测试里调用，`tok->audit` 恒 NULL，事件静默丢弃。
**定**：**批 1 就接上。** 这是零硬件风险、且比登记表任何一条都实的洞。

## 3. 落地顺序

### 批 1 — 不等 OP-TEE，关掉 CODE-1（纯 RTL / BL31 / 软件）
| 事项 | 说明 |
|---|---|
| 关掉 CODE-1 | 种子源收进 PL 内部（TRNG→种子内部通路 + "仅内部"单向闩），或至少收进 EL3；**不经普通世界** |
| 接上审计日志 | D9 |
| 软件收口 | 安全 profile 禁 `SEED_STORAGE`（消灭落盘种子路径）；非演示构建强制 device-dna KDR；修 ML-KEM 失败路径 `seed[]` 未清零、`session_end` 不清 `pay`/`out` 静态缓冲；`pqc_random_bytes` 判定改 `hwrng_is_hardware()` |
| 防回滚 | 接上 RPMB 写计数器 provider（**provision 保持编译期关**，只 verify/bump）；备份 blob 补设备绑定 epoch |
| 文档对齐 | REGISTERS 与 RTL 对齐（16 槽 / KEYPSET / MODE 字段）；修三处互相矛盾的擦除周期数 |

风险：位流可运行时换、断电回黄金槽。**先证明能 JTAG 救援再上板。**

### 批 2 — OP-TEE 上板后，编排上移 TA
| 事项 | 说明 |
|---|---|
| ① OP-TEE 真正启动 | 解决 BL32 入口死结。**不通则主线无从谈起** |
| ② EL3 世界分级 | D3。几十行，复用已验证的安全事务签发 |
| ③ 编排上移 | KEK/wrap/私钥编排搬进 TA（边界落在 `wrap.h`/`pqc.h`）；TA 经安全 SiP 驱动 PL；种子源改 TEE 安全存储；普通世界栈改 TA 客户端 |
| ④ 可选 | mTLS 设备私钥搬进 TA |

工程量最大的一批，且严格依赖 ①。软件侧准备度其实很高（vtable 形状天然匹配、域分隔与 KEK 轮换与
"根从哪来"正交），provider 近乎纯转接层。

### 产品化前置 — 依赖换硬件或量产载板，**不在原型范围内**
| 事项 | 依赖 |
|---|---|
| 硬件信任根 | 量产载板 + 烧写计划（认证根与秘密根**两套**）+ OP-TEE 供给 + 三个尚不存在的 KDR provider + 产线密钥保管（Bootgen HSM 模式、XLWPT 需向 AMD 索取） |
| 物理防篡改 | 新增 BOM（网格/传感器）+ 机械设计 + 台架验证 |
| 认证资质 | 下游于上面两项；流程、时间、第三方实验室 |

## 4. 红线（不因本方案而放宽）

⛔ **绝不烧 eFUSE、绝不动 BBRAM 锁存位、绝不重烧 RPMB 密钥、绝不做任何一次性/不可逆写入。**

红线的准确定义（`docs/SECURITY.md`）：**不可逆动作需板主显式同意，默认答案是不**——是一条可推翻的
默认拒绝，不是物理不可能。它现行的理由是"不可逆 + 只有一块板"，即**资源与流程约束，量产时自动失效**。

配套纪律：不可逆动作 + 会撒谎的状态读取 = 不可接受（RPMB `provision` 保持编译期关闭）。

## 5. 对外宣称口径（一句话版）

> 一台**以 PQC 硬件核为差异化**的密码机原型：ML-KEM 与 ML-DSA 全参数集在 FPGA 专用数据通路上
> 逐字节对齐 ACVP、硅上验证，密钥种子由 PS 的 TEE 保管、私钥不出芯片，
> 提供**运行时隔离 + 设备绑定**级别的保护。
> **尚不具备**硬件信任根、物理防篡改与合规资质——三者均为产品化前置，其中信任根是本项目红线
> 主动不做（硅上具备），另两项需新增产品硬件与认证流程。
