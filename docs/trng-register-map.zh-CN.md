# TRNG 寄存器表与驱动契约

这份文档是**安全世界驱动**与 **PL 里的 `trng_axi`** 之间的契约。两边各自照它写，
`hardware/tb/cocotb/test_trng_axi.py` 逐条验证。

与加速器（`docs/register-map.zh-CN.md`）不同，TRNG 是**常开自由运行**的外设：
没有"发命令→等完成"这一套，只有"暖机 → 就绪 → 取字"，外加一组健康状态。

---

## 一、地址表

基址由综合时的地址分配决定，全部寄存器 32 位、字对齐，地址译码用 `[5:2]`。

| 偏移 | 名字 | 软件 | 说明 |
|---|---|---|---|
| `0x00` | `CTRL` | 读/写 | `[0]` ENABLE（电平）`[1]` ZEROIZE（写 1 脉冲）`[2]` CLEAR_ALARM（写 1 脉冲） |
| `0x04` | `STATUS` | 读 | 见下表 |
| `0x08` | `RDATA` | 读 | **读一次弹出一个 32 位随机字** |
| `0x0C` | `HEALTH` | 读 | `[31:16]` APT 当前窗口计数，`[15:0]` RCT 当前游程 |
| `0x10` | `APT_INDEX` | 读 | 本 APT 窗口已处理的样本数 |
| `0x14` | `STARTUP` | 读 | 启动健康检测已通过的样本数 |
| `0x18` | `BLOCKS` | 读 | 调理器已吸收的 rate 块数 |
| `0x1C` | `WORDS` | 读 | 已交付给软件的字数 |
| `0x20` | `VERSION` | 读 | 常量 `0x0001_0000` |
| `0x24` | `PARAM0` | 读 | `{DECIM[7:0], NUM_RO[7:0], RATE_LANES[7:0], OUT_LANES[7:0]}` |
| `0x28` | `PARAM1` | 读 | `{APT_CUTOFF[15:0], RCT_CUTOFF[15:0]}` |
| `0x2C` | `PARAM2` | 读 | `{STARTUP_SAMPLES[15:0], APT_WINDOW[15:0]}` |

### STATUS 各位

| 位 | 名字 | 含义 |
|---|---|---|
| `[0]` | `READY` | 启动检测已过、无告警、未在擦除 |
| `[1]` | `DATA_VALID` | FIFO 里有字可读 |
| `[2]` | `ALARM` | 健康检测告警（锁存） |
| `[3]` | `RCT_ALARM` | 重复计数检测告警 |
| `[4]` | `APT_ALARM` | 自适应比例检测告警 |
| `[5]` | `STARTUP_DONE` | 启动健康检测已通过 |
| `[6]` | `FIFO_WIPING` | 擦除扫描进行中 |
| `[7]` | `ENABLED` | `CTRL.ENABLE` 的回读 |
| `[8]` | `UNDERRUN` | 曾经空读过 `RDATA`（锁存） |

## 二、行为契约

**`RDATA` 是读时弹出的。** 读一次消费一个字。软件**不能**对它做"读回校验"、
不能重读同一地址来确认，也不能在调试器里随手 dump 这段地址 —— 每次读都在
消耗熵。AXI4-Lite 没有推测读，所以一次读就是一次消费，不多不少。

**空读返回 0，并锁存 `UNDERRUN`。** 返回 0 本身是危险的：不看状态就读的驱动会
把 0 当随机数用。`UNDERRUN` 存在的意义就是事后抓住这种驱动 bug —— 它锁存，
只能由 `CTRL.ZEROIZE` 或 `CTRL.CLEAR_ALARM` 清。

> 驱动的正确用法：**每次读 `RDATA` 之前先读 `STATUS`，确认 `DATA_VALID`。**
> 取完一批之后再读一次 `STATUS`，确认 `UNDERRUN` 与 `ALARM` 都是 0，
> 否则这一批全部作废。

**`ALARM` 是锁存的电平，不是脉冲。** 与加速器的 `STATUS.DONE` 同一个理由：
软件在任意时刻轮询都必须能读到。清除只能靠 `CTRL.CLEAR_ALARM`。

**告警之后不是"清了就能接着用"。** 清告警会**重跑启动健康检测**：
`STARTUP_DONE` 归零、`STARTUP` 计数从 0 开始、海绵状态被清空。
在 `READY` 重新拉高之前，`RDATA` 不会有任何数据。

**`ZEROIZE` 与 `tamper` 引脚等价。** 两者都会：擦除 FIFO（逐地址覆零，不是只挪
指针）、清空 Keccak 海绵状态、清 `WORDS`/`BLOCKS` 计数、重跑启动检测。
区别只在触发路径 —— `tamper` 是硬件引脚，不经软件，软件被攻陷也擦得掉。

**`PARAM0/1/2` 是给启动自测用的。** 驱动初始化时读回这三个字，与自己编译期
的常量比对。这类不一致在真系统里出过事：改了 RTL 参数忘了改驱动，健康检测
看起来一切正常，实际判据已经不是标准要求的那个了。

## 三、AxPROT 安全门控

`SECURE_ONLY=1`（默认）时，`AxPROT[1]`（NS 位）为 1 的读写**一律返回 DECERR**，
并且**不产生任何副作用**。

返回 DECERR 而不是 OKAY+0 是有意的：静默返回 0 会让普通世界以为自己拿到了
随机数，而 0 是最糟的"随机数"。

**被拒的读绝不弹 FIFO。** 这一条单独说，因为它是最容易写错、后果又最实际的
一个。如果被 DECERR 拒掉的读仍然弹出，普通世界虽然拿不到数，却获得了一个
"反复读把熵池抽干"的手段 —— 让安全世界拿不到随机数，和自己拿到随机数，
是两个不同的攻击，后者一样致命。`test_trng_axi.py` 里有专门一条测它。

### 这一层不是唯一一层

AxPROT 门控是**纵深防御的最内层**。完整的隔离要三层一起：

| 层 | 位置 | 挡住什么 | 绕过它需要 |
|---|---|---|---|
| 地址映射 | 普通世界设备树 | 普通世界的 Linux 驱动 | 改设备树或直接 `/dev/mem` |
| XMPU / XPPU | PS 侧，master 那端 | 任何 master 发往这段地址的非法访问 | 改 PMU 配置（要安全世界权限） |
| AxPROT 门控 | PL 侧，slave 这端 | 带 NS=1 的事务 | 让某个 master 恒发 secure |

三层各有各的绕法，所以都要做。最后一列说明了为什么 AxPROT 单独不够：
它判的只是总线上那一位，**如果某个 master 被配置成永远发 secure，这一层就
形同虚设** —— 那正是 XPPU 该管的事。详见 `docs/xmpu-xppu-isolation.zh-CN.md`。

## 四、熵账与它的前提

| 项 | 取值 | 来源 |
|---|---|---|
| 噪声源 | 8 条环振（13/15/…/27 级），异或合并 | `trng_source.v` |
| 抽取比 | 每 8 个时钟取 1 个样本 | `DECIM=8` |
| 假设的每样本最小熵 | **H = 0.5 bit** | ⚠️ **尚未实测** |
| 连续健康检测 | RCT C=41，APT W=1024 C=793 | 按 H=0.5 现算，`trng_health_model.py` |
| 启动健康检测 | 1024 个连续干净样本 | SP 800-90B §4.3 |
| 调理 | Keccak 海绵，rate 1088 bit，capacity 512 bit | vetted conditioning，§3.1.5.1.2 |
| 每轮 | 吸收 1088 比特（544 bit 熵）→ 挤出 256 bit | 544 > 256，输出按满熵计 |
| 输出速率 @100 MHz | 256 bit / 87 µs ≈ 2.9 Mbit/s | 原型验证够用 |

> ⚠️ **整张表的前提是 H ≥ 0.5，而 H 尚未在硅上实测。**
> RTL 仿真里环振跑的是行为模型，抖动量是编的（见 `ring_osc.v` 文件头），
> 所以**任何最小熵数字都不能从仿真里得出**。上板之后必须：
> 1. 把原始比特（`DECIM` 可调，从 AXI 导出原始流）取够 1M 以上样本；
> 2. 跑 NIST EntropyAssessment（SP 800-90B 的官方工具）；
> 3. 按实测的 H 反过来定 `DECIM`、`RCT_CUTOFF`、`APT_CUTOFF`，
>    以及每次挤出前要吸收几个 rate 块（`ABSORB_BLOCKS`）。
>
> 在那之前，这些参数是**设计假设，不是结论**。
