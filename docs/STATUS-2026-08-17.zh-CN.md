## 一、这台密码机现在是什么

**密码边界是 FPGA fabric。** ML-KEM 核、ML-DSA 核、对称核（AES-128/256、SM4、SM3）、
环形振荡器熵源、片内密钥金库与访问门控全部在 PL 里。主机侧的 PKCS#11 / SDF 库、
keystore、槽位元数据跑在它**之外**。

### 能力清单

| 类别 | 能力 | 证据 |
|---|---|---|
| KEM | ML-KEM-512/768/1024 KeyGen / Encaps / Decaps | 真硅上逐字节对 NIST ACVP（20/20） |
| 签名 | ML-DSA-44/65/87 KeyGen / Sign / Verify | 真硅上逐字节对 ACVP（32/0，见下方 ⚠️） |
| 对称 | AES-128/256、SM4，ECB/CBC/CTR/CFB/OFB | 对 SP 800-38A / GB/T 32907 |
| 杂凑 | SM3 | 对 GB/T 32905 A.1 |
| 熵源 | PL 环振 + SP 800-90B 健康检测 | 调理前 H = 0.871 bit/sample；PL 重配重启矩阵 H = 0.507 ≥ 0.436 |
| 私钥保护 | 片内金库：`dk`/`sk` 不出总线，按槽号使用 | 读游标 seek 到 sk 段读回全 0，而按槽签出的 σ 与自送 sk 逐字节相同 |
| 接口 | GM/T 0018 风格 SDF、PKCS#11 v3.2 | `sdf_demo` 九节全绿；p11 演示 |
| 设备绑定 | 密钥派生根可绑 Device DNA（默认关） | 板上与远端主机两条路都跑通 |

⚠️ **ML-DSA 的 32/0 是在 SK_LOCK 闩上之前取的。** 闩上之后 KeyGen 只吐 `pk`，
ACVP 的 KeyGen 向量比对不了私钥 —— 那 6 条**必然**失败，**那是闩锁在正常工作**。
`mldsa_hwtest` 现在会把这句话直接打出来。要重取 KeyGen 证据：先重配 PL 清掉闩锁，
且别让 daemon 先起来。

### 明确**没有**的东西

* **没有安全启动**（第四节：BBRAM 死在没电池；PUF 根因已定位、修正镜像已构建，
  **但没上板验过**）
* **没有 SM2**
* **没有算法证书**（ACVP 向量是本地跑的，那是正确性证据，不是证书）
* **root 仍然能"用"密钥**（读不到私钥，但能命令硬件做运算 —— SiP 不校验调用来源）
* **root 仍然读得到 OP-TEE 的安全内存**（第三节 ②；根因这轮定了，修法未实施）
* **没有功耗/电磁侧信道对策**（刻意排除，理由见 SECURITY）

### ② XMPU / XPPU —— **根因这轮定了，缺口仍在**

第一会话的状态是"挡得住非安全 DMA 主控、挡不住 APU，**为什么需要 UG1085 才能定**"。

**定下来了，而且答案与 DDR 通路架构无关 —— 是 XMPU 的工作方式被理解错了。**

权威出处：**XAPP1320《Isolation Methods in Zynq UltraScale+ MPSoCs》v3.0
（2020-04-30）第 10 页**：

> "If an illegal transaction is attempted, the XMPU asserts AxUser[10] but the
> transaction **is passed to the memory controller**. This mechanism is referred to
> as poison by attribute. **The transaction is gated by the end point, not the XMPU
> itself.**"

**XMPU 只负责"检测 + 打毒标记"，真正掐掉事务的是终点（DDR 控制器）。**
而我们这份配置里毒化根本没开：

```
DDR0..5  CTRL   = 0x0000000b   → bit2 POISONCFG = 0
DDR0..5  POISON = 0x00000000   → ATTRIB(bit20) = 0，BASE = 0
```

现象因此完全自洽：**区域是对的、检测是活的（DMA 主控的违规被锁存了），
但没有任何东西去 gate，所以数据照样返回。**

**顺带排掉了三个假设**（都去查了 Xilinx 自己的定义，不是猜）：

| 曾经的怀疑 | 结论 | 出处 |
|---|---|---|
| `cfg=0x17` 的位定义抄错了 | **没抄错**，语义正确 | `xddr_xmpu0_cfg.h`；QEMU `hw/misc/xlnx-xmpu.c:205-228` 严格模式判据 `sec != regionns` |
| `ALIGNCFG=1` 让 START/END 变成 MB 单位，于是区域压根没覆盖 | **不是**。字段恒为 `addr>>12`，ALIGNCFG 只把区域**对齐**到 1 MB | QEMU `xlnx-zynqmp-xmpu.c:283-292`（`xr->start <<= 12`）与 327-328（`&= ~addr_mask`）。实测印证：`ERR_ADDR=0x0006002a` → `0x6002a000`，正落在区域内 |
| `MASTER=0` 被硬件当成"不匹配任何主控" | **不是**，掩码 0 即匹配所有主控 | QEMU 同文件 330 行 `(mask & id) == (mask & master_id)` |

**还剩一个二选一没分开**，而分开它只需要一次**只读**遍历（脚本已写好：
`board/scripts/verify_after_por.sh`）：

* 六个实例**全部**锁存到 APU 的主控号 → 到达了、也检测到了，**纯粹是没 gate**
  → 修法是开按属性毒化（改 BL31）。
* 仍有实例是 0 → **APU 的访问根本没到达 XMPU_DDR**，那是架构边界，如实写。

⚠️ `ERR_ADDR`/ISR 是**粘的**，只有 POR 能清。所以这个实验**一次断电只有一次机会**，
必须在任何别的主控违规之前做 —— 这就是它被放在 `verify_after_por.sh` 第一步的原因。

⚠️ 那份 XMPU 配置**留在 BL31 里**，因为它确实检测到了非安全 DMA 主控。但文档里
**必须**同时写明它挡不住 APU，否则就变成"看着像 OP-TEE 受保护了"。

证据：`board/logs/RESULT_protunit.txt`。

## 四、安全启动：能不能在铁律内做成

**铁律**：绝不烧 eFUSE；不装电池就没有 BBRAM。问题是——在这两条之下还剩什么。

### 先把天花板写死（这一条与做不做得成无关）

不烧 eFUSE 就没有 `ENC_ONLY` 和 `RSA_EN`，**BootROM 不强制加密、也不强制认证**。
攻击者换一份"声明为不加密"的镜像，BootROM 照启不误。

> **所以本项目在任何配置下都拿不到"防替换的信任根"。**
> 能拿到的上限是**机密性 + 设备绑定**。这一条**不是本轮的失败，是芯片的规则**。

### ⛔ BBRAM —— **受阻：板级硬件（`VCC_BATT` 没接电池）**

两个必要条件互斥，已用**两次物理断电**验到底（第一会话）：

* 烧钥匙 → 钥匙在，但 `BBRAM_STS.PGM_MODE` 锁成 1，**CSU 不把钥匙交给 BootROM**
* 断电清锁存 → 锁存清了，**钥匙也一起没了**

**要让它成立需要给 `VCC_BATT` 接一颗电池 —— 板级硬件改动，软件绕不过去。**

留下的可复用资产：`boot/persist/build_bbram_boot.sh`；加密镜像
`/media/sd-mmcblk1p2/hsm/BOOT_ENC2.BIN`（**不在任何启动槽**）。

### 🔶 PUF 黑钥 —— **根因定位到具体一字，修正镜像已构建，板上未验**

**先纠正一条此前文档里的错误**：`docs/SECURITY.zh-CN.md` 原来写着
"PUF 黑密钥依赖烧 eFUSE，已永久排除"。**这是错的。**
`bootgen -bif_help fsbl_config` 对 `bh_auth_enable` 的原文是
"RSA authentication … **excluding the verification of PPK hash and SPK ID**"，
AMD 的 Embedded Design Tutorial 也写明 PUF boot header 模式
"**does not require programming of eFUSEs**"。**这条路在铁律内是成立的。**

**上一轮被拒收的三个缺陷，全部有权威出处**：

| # | 缺陷 | 权威依据 | 旧镜像实测 |
|---|---|---|---|
| ① | bif 缺 `puf4kmode`（bootgen **默认 12K**，注册却是 4K） | `bootgen -bif_help fsbl_config` 原文 "(Default is 12k bit)"；注册端 `xilskey_puf_registration.h:148` = `XSK_PUF_MODE4K` | 启动头 `0x44` 的 `[17:16]` = **0**（应为 3） |
| ② | bif 缺 `shutter=0x0100005E` | 注册端 `xilskey_eps_zynqmp_puf.h:72` `XSK_ZYNQMP_PUF_SHUTTER_VALUE = 0x0100005e` | 启动头 `0x6c` = **`0x01000020`**（bootgen 默认值） |
| ③ | **辅助数据最后一字被上一轮"修"坏了** | `xilskey_eps_zynqmp_puf.c` 注册尾部：`Aux = (PufStatus & AUX_MASK) >> 4` 而 `SyndromeData[385] = (PufStatus & AUX_MASK) << 4` —— **差 8 位移位** | 写的是 `0x00864FE2`，正确值 **`0x864FE200`** |

**③ 是一次"修复"造成的回归，值得完整记下来**：

* 第一版把 `PufInstance.SyndromeData[]` 的 386 字**原样**写进 `puf_file` —— **那是对的**。
  库自己就会把 CHASH 放进 `[384]`、`AUX<<4` 放进 `[385]`。
* 然后在镜像里搜 `0x00864FE2` 搜不到，判定"AUX 没进去"，于是改成
  "384 字 + CHASH + AUX"。**搜不到是必然的** —— 真正该在那里的是 `0x864FE200`。
  **这个假阴性把一份正确的数据改坏了。**
* 佐证：文件里 `word[383]` 与 `word[384]` **都是 CHASH**。这不是错位，正是库的行为
  —— 4K 模式读数循环停在 `Index=383`，最后读到的那字就是 CHASH，随后又复制到 `[384]`。
  **说明只有最后一字是坏的。**

**本轮两次上板（都在非 golden 槽，golden 全程未动）**：

`insmod pmsec.ko set_multiboot=6` → `hsmreboot.sh` → 回来后读 `CSU_MULTI_BOOT`：
**6 = 成功，7 = 又被拒**。验完把槽 6 删掉、槽 7 还原
（备份在 `/media/sd-mmcblk1p2/hsm/BOOT0007_j1_backup.BIN`）。

⚠️ **不要先试带 RSA 的变体。** 它的失败模式是硬停、要断电；不带 RSA 的失败模式
是自己往下搜、板子不掉。**先跑安全的那个。**

### 其余可选手段（未做）

* **灰钥（`bh_gry_key`）**：不用 eFUSE 不用电池，但用的是 Xilinx **家族密钥**，
  **所有 ZU+ 芯片共用一把** —— 那是混淆，不是保护。
* **U-Boot 验证启动（FIT 签名）**：挡不住换 BOOT.BIN，但从 U-Boot 往上是一条
  真的完整性链。
* **装位流前校验**：`hsm-boot.sh` 在 `fpgautil` 之前先验 `.bit` 的哈希/签名。
  挡不住 root 绕过，但把"随便换个位流就换掉整个密码边界"抬高一档。

### ⚠️ J1（位流固化进 BOOT.BIN）—— **能启动，但那个形态掉网**

不再往下追：**它唯一的消费者是安全启动**，而演示形态在运行时装位流，网络和演示
都正常 —— J1 不是必需项。

## 六、怎么演示

**上电，等 35 秒。** 不需要任何操作 —— `fpga_manager` 报 `operating`、daemon 起好、
eth1 在 `192.168.50.175`。

```bash
# 本机（板子上）
/media/sd-mmcblk1p2/hsm/sdf_demo

# 远程（另一台机器，先从板子取一次性口令）
TOK=$(ssh root@192.168.50.175 cat /media/sd-mmcblk1p2/hsm/hsm_token)
./sdf_demo 192.168.50.175 "$TOK"
```

九节内容：PING / ML-KEM-768 三步 / SM4 密钥进硬件 / **ML-DSA 三个参数集** /
四种分组模式 / SM3 / 以及一条**反证**——断开重连后旧句柄必须失效。

配套单项工具（都在 `/media/sd-mmcblk1p2/hsm/`）：

| 工具 | 演示什么 |
|---|---|
| `dna_probe -w` | 设备绑定：读 DNA，并**正面验证写会被 EL3 拒绝** |
| `protunit_probe` | 保护单元实配（XPPU 关着、XMPU 区域、六实例状态） |
| `mldsa_hwtest` | ML-DSA 对 ACVP（注意 SK_LOCK，见第一节 ⚠️） |
| `dna-bind-check`（主机侧） | 远端主机把 keystore 绑到这块板 |
| `verify_after_por.sh` | **断电之后第一件事**：XMPU 的判决性只读实验（在仓库 `board/scripts/`，尚未进板，传法见第〇节） |

**掉网了怎么办**：先用串口**只读**看状态（`board/scripts/serial_console.py --watch N`），
别用串口打命令。再不行用 JTAG 清 `CSU_MULTI_BOOT` 加系统复位。
⚠️ **但 JTAG 救不回"BootROM 认证失败"那种硬停**（本轮实测，四种复位全部不支持
或无效）—— 那种情况只能断电。

## 七、done / blocked 一览

| 项 | 状态 | 根因与代价 |
|---|---|---|
| ML-KEM / ML-DSA / AES / SM4 / SM3 / TRNG / KEM-DEM | **done** | 真硅逐字节对标准向量 |
| 片内密钥金库 + SK_LOCK | **done** | —— |
| 设备绑定（Device DNA） | **done**，默认关 | 换根会让既有 keystore 打不开，必须人明确决定 |
| rtl_sim 回归 | **done** | 47/47（全量 251 用例） |
| golden 完整性 | **done** | 四份逐字节一致，有离板副本 |
| XMPU 挡非安全 DMA 主控 | **done（检测）** | 但**不 gate**，见下 |
| XMPU 挡 APU | **blocked** | 根因已定（XAPP1320：XMPU 不拦截，只毒化，由终点 gate）。修法要改 BL31 开按属性毒化；还差一次**只读**判决实验分开"没到达"与"没 gate"。代价：一次断电 + 一次 BL31 重建 |
| 安全启动 / BBRAM | **blocked（物理）** | `VCC_BATT` 没接电池。**要人装一颗纽扣电池**，软件绕不过 |
| 安全启动 / PUF 黑钥 | **blocked（待验证）** | 根因定位到辅助数据最后一字（`0x864FE200`），修正镜像已建并自检通过；**差一次上板**。代价：一次断电让板子回来，再跑一次槽 6 实验 |
| 防替换的信任根 | **永久排除** | 需要烧 eFUSE（`ENC_ONLY`/`RSA_EN`），不可逆 + 只有一块板 |
| SM2 | **未做** | 范围外 |
| 侧信道对策 | **刻意排除** | 无实验台就无法证明有效，理由见 SECURITY |
