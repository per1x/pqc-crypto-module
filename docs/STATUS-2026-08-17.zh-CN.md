## 一、这台密码机现在是什么

**密码边界是 FPGA fabric。** ML-KEM 核、ML-DSA 核、对称核（AES-128/256、SM4、SM3）、
环形振荡器熵源、片内密钥金库与访问门控全部在 PL 里。主机侧的 PKCS#11 / SDF 库、
keystore、槽位元数据跑在它**之外**。

### 能力清单

| 类别 | 能力 | 证据 |
|---|---|---|
| KEM | ML-KEM-512/768/1024 KeyGen / Encaps / Decaps | 真硅上逐字节对 NIST ACVP（20/20） |
| 签名 | ML-DSA-44/65/87 KeyGen / Sign / Verify | 真硅上逐字节对 ACVP（32/0，见下方 ⚠️） |
| 对称 | AES-128/256、SM4，ECB/CBC/CTR/CFB/OFB | 对 SP 800-38A / GB/T 32907 |
| 杂凑 | SM3 | 对 GB/T 32905 A.1 |
| 熵源 | PL 环振 + SP 800-90B 健康检测 | 调理前 H = 0.871 bit/sample；PL 重配重启矩阵 H = 0.507 ≥ 0.436 |
| 私钥保护 | 片内金库：`dk`/`sk` 不出总线，按槽号使用 | 读游标 seek 到 sk 段读回全 0，而按槽签出的 σ 与自送 sk 逐字节相同 |
| 接口 | GM/T 0018 风格 SDF、PKCS#11 v3.2 | `sdf_demo` 九节全绿；p11 演示 |
| 设备绑定 | 密钥派生根可绑 Device DNA（默认关） | 板上与远端主机两条路都跑通 |

⚠️ **ML-DSA 的 32/0 是在 SK_LOCK 闩上之前取的。** 闩上之后 KeyGen 只吐 `pk`，
ACVP 的 KeyGen 向量比对不了私钥 —— 那 6 条**必然**失败，**那是闩锁在正常工作**。
`mldsa_hwtest` 现在会把这句话直接打出来。要重取 KeyGen 证据：先重配 PL 清掉闩锁，
且别让 daemon 先起来。

### 明确**没有**的东西

* **没有安全启动**（BBRAM 那条见第四节；不烧 eFUSE = 没有防替换的信任根）
* **没有 SM2**
* **没有算法证书**（ACVP 向量是本地跑的，那是正确性证据，不是证书）
* **root 仍然能"用"密钥**（读不到私钥，但能命令硬件做运算 —— SiP 不校验调用来源）
* **root 仍然读得到 OP-TEE 的安全内存**（见第三节 XMPU）
* **没有功耗/电磁侧信道对策**（刻意排除，理由见 SECURITY）

## 二、两种形态

| | 演示形态（**默认**） | 送检形态 |
|---|---|---|
| 位流 | `zu3eg_hsm_dev.bit`，`SECURE_ONLY=0` | `zu3eg_hsm.bit`，`SECURE_ONLY=1` |
| 装载时机 | 开机后由 `hsm-boot.sh` 运行时装 | 同左 |
| 普通世界能否直接读密码核 | 能（`/dev/mem`） | **不能**（防火墙 RAZ/WI），只能经 `/dev/secmmio` → EL3 白名单 |
| 网络 | eth0 随 PL 消失，**eth1（PS GEM）不受影响** | 同左 |
| 上电到就绪 | 约 35 秒，全自动 | 同左 |

**默认就是演示形态**：上电 35 秒后 daemon 起好、`fpga_manager` 报 `operating`，
不需要任何人工操作。

⚠️ `hsm-boot.sh` 的顺序是死的：**先配好 eth1 并确认有载波，再碰 PL**。
没载波就跳过位流装载 —— 因为换位流会把 eth0 一起弄没，两条网都断就失联了。

## 三、本轮做完的事（逐项，含验证）

### ① 设备绑定密钥根 —— **完成**

评审点的"KDR 是编译进去的常量，keystore 拷到别的板照样开"已落地。

* BL31 白名单加了一个**只读**窗口 `0xFFCA0050-5C`（Device DNA 在 CSU 里，
  EL1 直读是总线错误 —— 板上实测 `devmem` 一律 Bus error）。
* **写会被拒是正面验过的**，不是只看源码：`dna_probe -w` 真发一次写，EL3 挡下来。
  （白名单表历史上漏过一行，光读代码不算数。）
* 取 DNA 两条路都走通了 —— 只做一条的话另一条就是"在源码里、永远跑不到"：
  * 库在板上 → 直读 `/dev/secmmio`（`board/src/dna_probe`）
  * 库在**远端主机** → 经 `OP_DEVICE_DNA` 取回（`tools/dna-bind-check`，
    已从 macOS 连板子跑通）。**真实拓扑是这一条。**
* 口径：加了 `device_bound` 字段，**没有**把 `hardware_backed` 改成 1。
  DNA 不是秘密，有 JTAG 就能读到 —— 给的是**防克隆**，不是机密性。
* 默认仍是桩，`PQCHSM_KDR=device-dna` 才切：换根会让既有 keystore 打不开，
  而且症状与被篡改一模一样。这种事必须是人明确决定的。

证据：`board/logs/RESULT_dna_bind.txt`（板上、远端、JTAG 三方读到同一个值）。

### ② XMPU / XPPU —— **部分完成，缺口如实标注**

先把"配了没有"变成可观测的：BL31 白名单开只读窗口（XPPU、XMPU_DDR0-5、
XMPU_FPD、XMPU_OCM）。在这之前从普通世界读保护单元自己的寄存器**一律总线错误**。

读出来的结果是一个**比预期严重的发现**：

```
XPPU_CTRL = 0                  —— XPPU 整个是关的
XMPU_DDR0..5 CTRL = 0xb        —— 默认放行读写，零个使能区域
root@petalinux:~# devmem 0x60000000 32
0xAA0003F3                     —— 一条 AArch64 指令 = OP-TEE 的安全世界代码
```

**即"密钥交给 OP-TEE 就受保护了"在这块板上不成立。**

修的部分：BL31 现在给 OP-TEE 的 core 段（`0x6000_0000+0x1000_0000`）在**六个**
XMPU_DDR 实例上各配一条安全区域（`cfg=0x17`，位定义抄自 Xilinx 的
`xddr_xmpu0_cfg.h`）。

* **挡住了**：`ERR_ADDR`/`ERR_MASTER`/ISR 三处一起证明区域是活的 ——
  非安全 DMA 主控 `0xa0`、`0xac` 被拒并锁存。**流氓外设 DMA 这条路堵上了。**
* **没挡住**：APU 自己的非安全读。同址与无 XMPU 那版逐字节相同。
  为什么，需要 UG1085 的 DDR 通路架构才能定。

⚠️ 中途两个把自己骗过去的观察，写进日志免得下次再上当：
① 区域内"没碰过"的地址读出 `0xFFFFDBF6` 一类值，看着像被拒 —— 不是，
那是未初始化 DRAM；保护区**外**的地址同样如此。判据只能是**同址前后对照**。
② `ERR_ADDR`/ISR 是**粘的**，锁存第一次违规就不再更新。

证据：`board/logs/RESULT_protunit.txt`。

### ③ rtl_sim 回归 —— **修好，251 个测试全过**

## 四、被卡住的两件（需要外力）

### ⛔ BBRAM 加密启动 —— **根因已定位，卡在需要一次物理断电**

**镜像是对的、密钥是对的、bif 是对的 —— 这次是线下证明的，不是推的。**

把镜像拉到本机离线解密：nky 的 `Key 0`（自然序）+ 启动头 IV，在
`fsbl_sourceoffset = 0x2800` 处，**48 字节安全头 + 16 字节 GCM tag 校验通过**，
解出的明文正是 ZynqMP 安全头该有的样子（32 字节全 0 = 不换钥、12 字节 = `IV 1`、
4 字节 = 字数，正好对上 pmufw 长度）。

**卡点：`BBRAM_STS`（`0xFFCD0000`）bit0 `PGM_MODE` 烧完之后一直锁在 1。**
锁着时 CSU 不把密钥交给 BootROM，加密 FSBL 解不开 —— 串口零字节、没有 FSBL 横幅、
APU 不放出来，与观测完全一致。清不掉它的四种做法都试过：

| 试过 | 结果 |
|---|---|
| XilSKey 自己的 `PrgrmDisable()` | 执行了，仍是 1 |
| JTAG 直接写 0 到 `0xFFCD0008` | 仍是 1 |
| JTAG `rst -system` | 仍是 1 |
| Linux 走 PMU **system 域**复位 | 仍是 1 |

**剩下唯一没试的是 POR（物理断电）** —— 这也正是 Xilinx 的标准流程。
XSDB 的 `rst -type ps-por` 只支持 Versal，ZynqMP 没有软件 POR 通路。

**需要你做的：断一次电。** 之后：

```bash
ssh root@192.168.50.175 "cp /media/sd-mmcblk1p2/hsm/BOOT_ENC2.BIN /media/sd-mmcblk1p1/BOOT0006.BIN; sync"
```

再用 JTAG 设 `CSU_MULTI_BOOT=6`、从 Linux 重启。两种结果都有信息量：

* **能起** → POR 清掉了 `PGM_MODE` 且 BBRAM 有电池 → 加密启动成立。
* **起不来且 BBRAM 读出 ZEROIZED** → 这块板 `VCC_BATT` 没接电池，
  每次断电都要重烧密钥，加密启动没有实用价值。
  （`VCC_BATT` 有没有接，本项目**从没验证过**，这一步顺带回答。）

**断电是安全的**：golden `BOOT.BIN` 是明文头、`ENC_ONLY` 没烧，BootROM 根本不看
BBRAM，随时断电都能起来。起不来的加密镜像**不在任何启动槽**里
（放在 `/media/sd-mmcblk1p2/hsm/BOOT_ENC2.BIN`）。

⚠️ 即便它跑通，口径也只能是**机密性 + 可恢复**：不烧 eFUSE 就没有 `ENC_ONLY`，
攻击者换一份声明为"不加密"的镜像，BootROM 照启不误。**加密挡不住替换。**

### ⚠️ J1（位流固化进 BOOT.BIN）—— **能启动，但那个形态掉网**

镜像用当前 BL31 重建、放槽 7 启动：四个 A53 都是 `Running`，**内核起来了**，
但板子网络够不着、串口也不给提示符。已按纪律恢复到 golden。

不再往下追的理由：**它唯一的消费者是安全启动，而安全启动本身被上面那条卡着**。
演示形态在运行时装位流，网络和演示都正常 —— J1 不是必需项。

## 六、怎么演示

**上电，等 35 秒。** 不需要任何操作 —— `fpga_manager` 报 `operating`、daemon 起好、
eth1 在 `192.168.50.175`。

```bash
# 本机（板子上）
/media/sd-mmcblk1p2/hsm/sdf_demo

# 远程（另一台机器，先从板子取一次性口令）
TOK=$(ssh root@192.168.50.175 cat /media/sd-mmcblk1p2/hsm/hsm_token)
./sdf_demo 192.168.50.175 "$TOK"
```

九节内容：PING / ML-KEM-768 三步 / SM4 密钥进硬件 / **ML-DSA 三个参数集** /
四种分组模式 / SM3 / 以及一条**反证**——断开重连后旧句柄必须失效。

配套单项工具（都在 `/media/sd-mmcblk1p2/hsm/`）：

| 工具 | 演示什么 |
|---|---|
| `dna_probe -w` | 设备绑定：读 DNA，并**正面验证写会被 EL3 拒绝** |
| `protunit_probe` | 保护单元实配（XPPU 关着、XMPU 区域、六实例状态） |
| `mldsa_hwtest` | ML-DSA 对 ACVP（注意 SK_LOCK，见第一节 ⚠️） |
| `dna-bind-check`（主机侧） | 远端主机把 keystore 绑到这块板 |

**掉网了怎么办**：先用串口**只读**看状态（`board/scripts/serial_console.py --watch N`），
别用串口打命令。再不行用 JTAG 清 `CSU_MULTI_BOOT` 加系统复位 —— 本轮用了六次，
六次都成，**一次电都没断**。
