# 密钥仓寄存器表（`key_vault_axi`）

AXI4-Lite 从机，32 位寄存器，地址窗口 **0x00 ~ 0x3F**（越界一律 DECERR）。

RTL 在 `hardware/rtl/bus/key_vault_axi.v`，测试在
`hardware/tb/cocotb/test_key_vault.py`。

---

## 这块外设存在的理由

一句话：**让"密钥不出密码边界"成为一个电路事实，而不是一条纪律。**

普通做法是把密钥放在内存里，靠软件不去读它。那要求每一处访问都记得判权限，
漏判一处就是一个安静的洞。这里的做法是：密钥寄存器与 `s_axi_rdata` 之间
**根本没有导线**。软件能做的只有四件事 —— 写进去、标记锁定、擦掉、
问一句"这个槽有没有装"。要用这把密钥，只能由 PL 里的算法核通过 `use` 口取，
那根线不出芯片。

这条不变量在 `test_key_never_readable` 里是**逐字扫描整个 256 字节地址空间**
验证的：八个槽全装上互不相同的密钥，扫完所有可读地址，断言 64 个密钥字一个
都不出现。**这条用例验过会咬人** —— 往读多路选择器里接一个密钥字，它立刻
报出泄漏的地址和值。

## 寄存器

| 偏移 | 名称 | 读写 | 说明 |
|---|---|---|---|
| 0x00 | `VERSION` | R | 版本号，默认 `0x0001_0000` |
| 0x04 | `CTRL` | W | `[0]` ZEROIZE：写 1 触发全局擦除，自清 |
| 0x08 | `STATUS` | R | `[0]` READY（未被篡改锁存）<br>`[1]` TAMPER_LATCHED<br>`[2]` DENY（有操作被拒，锁存，ZEROIZE 清） |
| 0x0C | `SLOT_SEL` | RW | `[2:0]` 当前操作的槽位 |
| 0x10 | `KEY_IN` | W | 写入一个 32 位字，字下标自动推进。**读恒为 0** |
| 0x14 | `SLOT_CTRL` | W | `[0]` BEGIN `[1]` COMMIT `[2]` LOCK `[3]` ERASE（写 1 触发） |
| 0x18 | `SLOT_STAT` | R | `[0]` VALID `[1]` LOCKED `[7:4]` 已写入字数 |
| 0x1C | `VALID_MAP` | R | 每槽一位 |
| 0x20 | `LOCK_MAP` | R | 每槽一位 |
| 0x24 | `ZERO_CNT` | R | `[7:0]` 全局擦除发生过几次（饱和） |
| 0x28 | `VIOL_CNT` | R | `{读违规[31:16], 写违规[15:0]}`，饱和 |
| 0x2C | `VIOL_INFO` | R | `[7:0]` 首次违规地址 `[8]` 是写 `[9]` NS 位 `[10]` 有效 |
| 0x30 | `PARAM0` | R | `{WORDS[15:8], SLOTS[7:0]}`，供驱动自检 |

**这张表里没有一个地址会返回密钥材料。** `KEY_IN` 是只写口，读它返回 0 ——
不是"被门控成 0"，是这一支本来就没连到密钥寄存器。

## 装载一把密钥

```
写 SLOT_SEL   = n                 选槽
写 SLOT_CTRL  = BEGIN             清该槽的字下标与 VALID
写 KEY_IN     × 8                 依次写入 8 个 32 位字（共 256 bit）
写 SLOT_CTRL  = COMMIT            置 VALID
写 SLOT_CTRL  = LOCK （可选）      之后写不进、擦不掉
```

### 半把密钥不算密钥

`COMMIT` 只在**整把密钥都写齐**时才置 VALID。写了 7 个字就 COMMIT，槽位仍然
无效，并且置 `STATUS.DENY`。这不是洁癖：半把密钥比没有密钥更危险 ——
它看起来是一把可用的密钥，实际上后半段是零。

### 锁定与擦除的关系

- `LOCK` 之后：`BEGIN` / `KEY_IN` / `ERASE` 全部被拒（AXI 仍返回 OKAY，
  但操作不生效并置 `DENY`）。
- 但 **`CTRL.ZEROIZE` 清得掉锁定的槽**。否则一把锁死的密钥会永远占着仓位，
  连重新灌装都做不到。锁保护的是"不被误改"，不是"不可销毁"。

## 擦除与篡改

| 触发 | 效果 | 能否恢复 |
|---|---|---|
| `CTRL.ZEROIZE` | 一拍清空全部槽位、VALID、LOCK；`ZERO_CNT` 加一 | 可以，重新装载即可 |
| `tamper` 引脚 | 同上，**并锁存** `TAMPER_LATCHED` | **只有 `rst_n`** |

`tamper` 引脚接板级的机箱开盖、电压/温度越界、JTAG 插入等检测。它拉高之后：

- 所有槽位立刻清零，`use_key` 恒零、`use_valid` 恒零；
- 防火墙转为 **fail-closed**：连读 `STATUS` 都返回 DECERR；
- **软件没有任何一条路能把它清掉。**

最后一条是有意的。真密码机检测到物理攻击之后本来就要重新灌装，
"软件可以宣布警报解除"恰恰是被攻陷的软件最想要的能力。

### 为什么擦除是一拍完成的

密钥存在寄存器阵列里而不是 BRAM。BRAM 只能逐地址写零，擦除过程中存在一个
"擦了一半"的窗口 —— 掉电或复位卡在那个窗口里，残留就还在片上。
寄存器阵列一个时钟沿全清，没有这个窗口。

代价是 8 槽 × 256 bit = 2048 个触发器（这颗片子的 1.5%）。
`tools/rtl_synth_check.sh` 会把它列进"摊成寄存器的存储"清单里 ——
那是**故意的**，不是 S3 那个 16 KiB 缓冲的重演。判断标准是规模：
这里 2048 bit 付得起，那里 16 KiB 付不起。

## 防火墙

`key_vault_axi` 里的 `axi4lite_firewall` 决定"这笔访问该不该存在"。
不合规的事务**根本不会出现在下游接口上** —— 下游从机看到的每一笔访问都是
已经被放行过的，从机里不必、也没有再判一次。

拒绝的条件（全部是编译期 parameter，没有任何总线路径能改）：

| 条件 | 默认 |
|---|---|
| `AxPROT[1] == 1`（non-secure） | 拒绝（`SECURE_ONLY=1`） |
| 地址不在 `0x00~0x3F` | 拒绝 |
| `TAMPER_LATCHED` | 拒绝一切 |

### "拦下来"和"到了但被忽略"是两回事

这是本模块最值钱的一条。`trng_axi` 里那份内联门控是"事务进到从机内部、
效果被门控信号掐掉"——那要求从机里每一处副作用都记得判那个信号。
独立的防火墙把边界前移：不合规的事务连下游的握手都不会发生。

`test_nonsecure_blocked_without_side_effects` 直接测这件事，用的是最狠的那个
操作：**non-secure 反复写 `CTRL.ZEROIZE`**。如果实现是"到了再忽略"，
只要哪一处漏判就是一次远程擦库。这条用例也验过会咬人 —— 把防火墙改成
"照样转发、只是回 DECERR"，六个用例挂五个。

### 违规留痕

拦下来只是第一步。拦下来这件事本身必须留痕，否则"没被攻击"和"被攻击了但
没人知道"长得一模一样。`VIOL_CNT` 是饱和计数，`VIOL_INFO` 记的是**第一次**
违规的现场（地址 / 读写 / NS 位）—— 取第一次而不是最后一次，因为第一次
通常是探测，最后一次往往已经是扫描产生的噪声。

## 纵深防御里的位置

这一层是**最内层，不是唯一一层**。真正的隔离还要靠：

- **XMPU/XPPU** 在 PS 侧就拦住到这段地址的非法访问（在 master 那端挡掉）；
- 地址映射本身不出现在普通世界的设备树里。

三层都做，是因为任何一层单独都可能被绕：`AxPROT` 判的是总线上的一位，
如果某个 master 被配置成永远发 secure，这一层就形同虚设 —— 那正是 XPPU
该管的事。分工见 [xmpu-xppu-isolation.zh-CN.md](xmpu-xppu-isolation.zh-CN.md)。
